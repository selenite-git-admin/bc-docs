# BCF metric-seed-driven characteristic discovery — broadened admission evidence + base-vs-derived gate

> **Provenance.** Re-materialized on 2026-08-22 (SES-c2bd78) from the DevHub decision registry (`decision_text`, row created 2026-06-26); the ADR file had never been written to bc-docs (registry `file_path` pointed at the pre-D373 `docs/adrs/` location). Content below is the registry text verbatim. Frontmatter per D373/D334.

## Decision

Establishes a metric-seed-driven characteristic discovery path that broadens BCF vocabulary admission beyond OAGIS source-field attestation while preserving the anti-model-memory grounding discipline. Five provisions:

(1) BROADENED ADMISSIBLE EVIDENCE (amends Vocabulary Admission Checklist M1). The bounded-evidence corpus widens from {OAGIS source field} to: a NAMED enterprise-system source field (e.g. SAP, Workday/SuccessFactors, Oracle HCM, Salesforce, IBM Maximo, ServiceNow); OR a published cross-industry standard (e.g. GS1, HR-XML / HR Open Standards, HL7, FpML); OR a published compliance/regulatory standard (e.g. ISO 30414, ISO 45001, IFRS, US GAAP, SOX). M1's REQUIREMENT is unchanged — every APPROVE still cites a named, attestable source. What broadens is the admissible source vocabulary, NOT the grounding obligation. Pure unattributed general knowledge / model-memory / 'common sense' remains inadmissible.

(2) DEMAND + GROUNDING GATE. A new characteristic on this path requires BOTH: (a) DEMAND — at least one mcf.seed_metric requires the value-property (traceable: characteristic <- seed_metric refs); and (b) GROUNDING — a named source/standard citation per (1). Demand alone does not admit; grounding alone does not admit. The seed provides demand + usage context; the named source/standard provides meaning attestation.

(3) BASE-vs-DERIVED GATE (the PRIMARY filter for this path). Metric-seed extraction MUST classify each referenced property as a BASE value-property (directly observed -> characteristic candidate) or a DERIVED/COMPOSITE measure (computed/qualitative metric output -> NOT a characteristic; it is itself a metric). Only base value-properties are admission candidates. Derived measures (e.g. candidate quality, workforce agility index, cultural health index, survey-composite scores, ROI) are rejected from the characteristic path and, where needed, become metrics. The HR probe showed ~half of referenced properties are derived; without this hard filter the registry would flood with non-characteristics.

(4) ENTERPRISE-SYSTEM DOMAIN KNOWLEDGE is admissible ONLY as a named-source citation (it names the system/standard grounding the property), never as standalone grounding. Domain knowledge proposes the source; the named citation grounds it.

(5) DISCOVERY PIPELINE. extract (batched/clustered over the 12,507 mcf.seed_metric rows; exploit raw_json.co_bindings / sources where present) -> classify base/derived -> dedup -> gap-analyze vs active characteristics -> ground each (named source/standard) -> admit via the panel (v1.2 calibration; M5/M6/M9 + admission_scope guards intact) -> auto-draft -> activate. Each admitted characteristic carries demand provenance (seed refs) + grounding citation.

All other admission discipline (M5 no-synonym, M6, M9 no-source-copy, admission_scope DEC-ec341c, immutability DEC-26b6e2, v1.1/v1.2 calibration DEC-45c01b) remains in force unchanged.</decision_text>
<parameter name="rationale_text">P1 characteristic enrichment from the OAGIS-finance catalogue (217 candidates) resolved to ~37 active characteristics, but coverage is finance-only. P3 metrics span 19 functions (mcf.seed_metric = 12,507 seeds: HR, IT-operations, operations, supply-chain, etc.) requiring value-properties OAGIS does not carry; the source-attested-OAGIS rule cannot ground them, so a broadened path is required to close the P3 coverage gap. The risk in relaxing input rules is re-admitting the model-memory / fake-green vocabulary that the v1.1/v1.2 discipline (DEC-45c01b) just eliminated; the design therefore broadens the EVIDENCE CORPUS (named sources/standards) while keeping the GROUNDING REQUIREMENT (a named attestable citation), and bounds production by metric demand (no over-production). HR extraction probe (2026-06-26): ~1,246 HR seeds -> ~15 distinct base characteristics (massive dedup from seed count); ~half of referenced properties are derived measures (not characteristics) -> base-vs-derived gate essential; every base property grounds to a named source (Workday/SuccessFactors/Oracle HCM) or standard. Decisively, the seed taxonomy ITSELF carries ISO subfunctions (iso_45001, iso_29990, iso_37002, iso_18001) -> compliance-standard grounding is already in the demand signal, not a model-memory backdoor. Extrapolation: ~150-250 distinct new characteristics across 19 functions (cross-function overlap on headcount/incident/training/survey/date-events) -> modest admission volume (~$60-100); the extraction over 12,507 seeds is the principal work. The named-source + demand + base/derived design preserves Foundation Invariant I (meaning produced once at its boundary) and the no-model-memory intent of M1 while extending coverage to the full enterprise-metric demand. Amends M1; does not weaken it.</rationale_text>
