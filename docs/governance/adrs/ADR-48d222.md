# Atomic Proof for Metric Evaluation — local Evidence+Lineage join the Snapshot transaction; WORM archive best-effort (resolves FND-AUTH-001)

## Context

Foundation Invariant VI (evidence emitted, not inferred) and the evaluation-boundary chapter require Evidence and Lineage to be written in the SAME boundary act as the authoritative object; absent proof means the object is not authoritatively proved. The external auditor encodes this as the active control FND-VI = `atomic_snapshot_evidence_lineage_write`.

DEC-ebb3cd D-1 (decided 2026-04-28) instead made Evidence/Lineage writes BEST-EFFORT: a failed proof write does not roll back the authoritative object; it is recorded via a `proof_status` (complete|partial|degraded) marker. Its stated rejection of strict-synchronous was motivated by the S3/network hot-path ("a transient S3/network blip becoming a runtime failure").

These two authorities conflict. The conflict is the retained finding FND-AUTH-001. It surfaced concretely in E6-B (TSK-c9ad19), which adds first-class metric-evaluation Lineage to the governed MCF runtime and cannot claim Invariant-VI closure while the posture is unresolved. Conformance to DEC-ebb3cd does not create Foundation PASS.

## Decision

**No proof, no record — this is the BareCount principle.** For metric evaluation, the local RDS Evidence and Lineage rows are written ATOMICALLY in the same tenant transaction as the Metric Snapshot. If the Evidence or Lineage write fails, the whole act (including the Snapshot) rolls back — there is no metric value without its proof. This satisfies Foundation Invariant VI / FND-VI and resolves FND-AUTH-001 in Foundation's favor.

**DEC-ebb3cd D-1 best-effort is authoritatively RE-SCOPED, not overridden wholesale.** Best-effort applies ONLY to the S3 WORM archive publication, which stays DEFERRED to post-commit and non-blocking (the mounted `createEvidence(dto, tx, deferredArchives)` seam). D-1's real concern — a remote/flaky S3 write killing an evaluation — is fully preserved. DEC-ebb3cd D-2 (one Lineage per evaluation with fromObjects[]/toObjects[]) is unchanged and remains the cardinality contract.

**Consequence for `proof_status`:** under the atomic local posture there is no "Snapshot with degraded RDS proof" state — a failed RDS proof write yields no Snapshot at all. `proof_status = degraded` is therefore reduced to a marker for deferred WORM-archive completeness only (archive-completeness, not proof-existence), and is no longer required to make metric evaluation Invariant-VI-compliant. It is deferred to its own governed unit if/when archive-completeness surfacing is needed.

## Scope

- **In scope now (E6-B):** metric evaluation (governed MCF runtime) — the atomic local Evidence+Lineage write in the persistence adapter's commit transaction, WORM deferred post-commit.
- **Already conformant:** the admission-batch path already writes Evidence+Lineage in-transaction with WORM deferred.
- **Follow-up alignment (separate units, not E6-B):** the currently fail-open boundary services (observation, canonical single-item, action, evaluation) are brought to the atomic local posture in their own governed units.

## Authority

Operator decision (founder / Principal Architect), 2026-08-19: "atomic — no proof, no record; that is BareCount." This ADR is the adopted authority artifact E6-B builds on. It reconciles FND-AUTH-001; it does not supersede DEC-ebb3cd (D-2 intact, best-effort intact for the S3 archive).
