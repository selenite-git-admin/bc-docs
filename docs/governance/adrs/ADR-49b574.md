# Demo-plane multi-metric generalization: document_currency COUNTs prove on the existing v5 grid + first count candidate

## Context

Codex gen-475639 (round 2, 2-round cap) accepted the generalization skeleton direction but flagged two blocking gaps — count/proof-grain and candidate selection — and routed a narrowed successor unit to the operator. This companion resolves both at source. The central reconciliation: Codex's Finding-1 premise (these COUNTs carry aggregation_currency_code=not_applicable, read from a corrective-target v2 classification) is contradicted by the live active MCVs (all document_currency); Codex's mechanism (assembler adds the currency key only for document_currency) is correct and, applied to the true value, CONFIRMS that the COUNT partitions by currency and fits the existing grid. Recording as PROPOSED follows Codex's bounded acceptance ("recording the proposed companion ADR may follow this bounded design acceptance"); no build, PR, merge, DB write or live-proof authority is conveyed.

## Decision

Companion to the demo-plane multi-metric generalization skeleton (Codex gen-475639, accepted direction; this narrowed successor accepted ACCEPTED-WITH-BOUNDARY as Codex gen-e64713-01, commit cea9cf01, sha256 362b5479). EXTENDS DEC-e8dd2d (oracle-authoring provenance) and AMENDS DEC-1bb88e act H (metric-version world binding); it does NOT supersede either, and it CONSUMES — does not re-open — DEC-1bb88e act D (the res.currency ISO normalization).

RULING (A) — COUNT proof-grain. A finance COUNT whose ACTIVE MCV reads aggregation_currency_code=document_currency proves on the EXISTING v5 (legal entity, ISO currency, period) demo proof grid (demo.fn_emit_demo_proof_v5, bc-db 0059/0060). It requires NO new count grid, NO new CLI dispatch, and NO bc-db grid migration. Grounded at source (bc_platform_dev live, served build bc-core 04e2615b): (1) all five sound finance primaries' active MCVs read document_currency (mcf.metric_contract_version, is_current), NOT not_applicable; (2) metric-spec-assembler.ts (L244-245) adds the currency snapshot key iff document_currency AND the grain CC declares currency_code, and cc-das36 5.1.0 declares currency_code (contract.canonical_contract_version body.field_selection + resolved_schema) — so a document_currency COUNT DOES partition by currency, which is the governed semantics the contract declares; (3) demo-commit-ccy-grid.ts (L48-54) refuses by name any non-ISO-4217 currency grain, requiring the CO's currency partition to be ISO — joined from res.currency at admission, never an id; (4) demo.co_cc_das36_v5_1_0 already carries ISO currency_code (INR/USD) per the already-realized DEC-1bb88e act D normalization (TSK-b5de1a, repair A+C; manufacturing ISO at the grid/evaluator is forbidden); (5) the builder Step-A oracle (INR 63/USD 6) is already in v5-grid shape with an 82-cell 0-diff cross-check, with the engine dry-eval unrun only because of the three skeleton blockers (G1/G2/G3), no grid blocker hit. FIX = currency normalization only (already done). A currency-agnostic count grid would be needed ONLY for a not_applicable COUNT, of which there are none among the sound finance primaries — out of scope.

RULING (B) — first candidate. customer_invoice_volume is THE first count candidate: its filter document_type_code=customer_invoice (mcf.metric_filter_clause) selects a non-empty subset of the admitted population (OC admits out_invoice/out_refund; the CO store carries 2453 INR + 246 USD customer_invoice rows). customer_payment_count is DROPPED: it filters document_type_code=customer_payment on the same Customer-Invoice grain (grain entity 127c57af) whose CO store carries ZERO customer_payment rows (wrong-population, confirmed by data, not only by the prior committed design DESIGN-customer-invoice-document-type-code-prove-on-one-2026-10-19); a general referee cannot repair a wrong-population MCV. overdue_payables_count, total_je_lines, total_journal_entries grain on CCs with no demo CO store => R3/R4 per-CC onboarding, out of scope.

REVISED MINIMUM-CUT BUILD SCOPE (for the first NEW finance Demoed, customer_invoice_volume): DROP the count-proof-grid/dispatch item that the skeleton's corrected minimum cut carried. The minimum cut = G1 (generic AdmittedSoReferee + closed recompute-recipe family; the strategy for customer_invoice_volume is count_rows, matching count(temporal_anchor) row-count semantics, NOT count_distinct) + G2-B1 (append-at-key pin kaveri-demo-v3lc5 -> {customer_invoice_volume e6438795 -> v1}) + G3 (DEMO_DATABASE_URL to the CLI process env, never the served bundle). No new grid, no serve-move (CLI lane).
