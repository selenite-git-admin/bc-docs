# Adopt "Integrity Assurance" as the platform thesis + retire "certified" as a product claim (vocabulary-authority, additive only)

## Context

The 2026-10-08 Integrity-Assurance thesis was an operator decision (ADOPTED + LIVE, memory project_barecount_product_thesis_2026_10_08) but was never formalized as an ADR, and vocabulary.md §7 requires ADR + desk-grant backing per slice — so Docs correctly refused to transcribe on the memory alone (TSK-3890ed snag). This thin ADR records only the already-decided, clearly-additive part so the clean doc slice is unblocked, while deliberately walling off the state-word lifecycle + Foundation-state renames that §8/§2-rule-3 reserve to operator + Architect. Operator confirmed recording it 2026-10-13. Keeping scope minimal avoids an open vocabulary/calibration rabbit-hole (cf. DEC-f21388 discipline).

## Decision

Formalizes the operator's 2026-10-08 thesis adoption so bc-docs vocabulary.md §7 has a citable ADR for the additive slice. TWO additive points only: (1) The platform's product thesis is INTEGRITY ASSURANCE — the deterministic machine gate is the primary, hard guarantee, with a residual true-meaning panel; this is the philosophy label the docs may use. (2) "Certified" is retired AS A PRODUCT CLAIM (the platform does not market a metric as externally "certified"); it says what it actually asserts — definitional validity through the integrity bar. This is explicitly NOT a rename of any Foundation/lifecycle STATE: the internal state named "active"/certification state machine is UNCHANGED by this ADR. SCOPE BOUND — this ADR does NOT decide, touch, or authorize any change to the state-word lifecycle (realized / active / validated / released) or any Foundation state rename; all of those remain reserved to the operator + Architect (vocabulary.md §8, §2 rule 3; "validated" is additionally Phase-C/tenant-zone per DEC-f21388-sibling reasoning). Docs may transcribe ONLY the two additive points above, citing this ADR.
