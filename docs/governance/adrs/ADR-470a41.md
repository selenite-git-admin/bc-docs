# E0: RuntimePlane on the evaluation read path + plane-aware guarded data-plane acquisition

## Context

DEC-89db41 generalized D575's single hard-coded `tenant` runtime plane to a declared set RuntimePlane ∈ {tenant, demo} AT THE CONNECTION/ISOLATION LAYER, and that layer is built and served (DemoConnectionService + demoDataEntry + the demo identity predicate exist). G0 found, and the Chief verified at source, that the generalization has NOT reached the EVALUATION READ PATH: every stage that acquires a data handle to read canonical facts / write a snapshot is still hardcoded to the tenant plane, and the demo plane is wired into the module but referenced by zero chain files. This ADR decides how the eval read/write path acquires its data plane so a metric evaluates against the demo plane exactly as against a tenant — consuming declared concepts, not raw fact shape, with no per-metric fact-shape coupling (G0's GO-A premise).

Verified at source (bc-core @ a9ea14b8, 2 commits behind origin/main @ f52bca2a by a pure fast-forward; the 2 unpulled commits are the #987 demo-loader write-path RUNNER and touch no eval-read-path surface):
- One guarded core already serves both planes: runGuardedPlaneTx(root, mode, fn, assertIdentity) (tenant-tx-runner.ts:71) — BEGIN read only|read write → assertIdentity(raw) as the FIRST statement → fenced Drizzle handle → COMMIT iff fn resolves. runGuardedTenantTx (:103) and runGuardedDemoTx (demo-tx-runner.ts:31) are thin wrappers differing only in (root, assertIdentity). The identity judge runtimeIdentityViolations(row, role) is already role-parameterised; the demo predicate reuses it.
- The two acquisition surfaces are NOT shape-symmetric yet: TENANT_DATA_DB hands a raw request-scoped handle (deprecated D575 W6-U5), guarded replacement TenantConnectionService.run(dbName, mode, fn) exists (:105); DEMO_DATA_DB is a frozen guarded { run(mode, fn) } with no raw handle — the demo plane is already at the terminal shape.
- A seam migration is actively erasing the asymmetry: d575-tenant-tx-seam.spec.ts is a shrink-only register (baselines forTenantData=15, tenantDataToken=25, rawTenantConnection=0; serve-move requires all three empty; demo describe-block zero-tolerance, no baseline). E0 sets the shape the seam shrinks toward.
- The evaluator core is plane-agnostic already (G0 re-confirmed): governed-metric-runtime.ts is pure/no-DB; the spec + bindings load from CONTROL_PLANE_DB; once facts are canonical the computation is declaration-driven.

FOUNDATION CHECK (architectural change — gate applies, DEC-79b62f):
1. Why this location (B+C)? The gap is a missing declaration — the data plane is an implicit tenant assumption; RuntimePlane declares it (B) and binds the demo acquisition (C). Matches DEC-89db41's own repair-location naming.
2. Why not an upper layer? A/B above are specified: DEC-89db41 already declared RuntimePlane ∈ {tenant, demo} at the contract level; E0 is the C/D realization of an existing declaration, not compensation for a missing one.
3. Why not a lower layer? A lower-layer fix would be Option B — a demo-specific eval path at repair-location D. That is the forbidden lower-layer compensation and is rejected.
4. Design act or execution act (DEC-c48b0f)? Design act — a declaration (RuntimePlane as an explicit reference + the plane-parametric acquisition contract), not a detector/net.
Invariant IV (references are explicit): satisfied — the data plane moves from an implicit tbc_${slug} assumption to a declared RuntimePlane reference threaded explicitly. No other invariant is touched (no meaning re-evaluation, no ordering change, no mutation of state, reads still never trigger evaluation).

SEQUENCING (Chief-held, nothing live): E0 ADR proposed → operator ratifies proposed→decided via a recorded desk grant → Chief sequences E1 (move ~8–10 eval-path callers onto planeConnection.run, riding the seam) + E2 (demo persistence adapter + tenantSlug→RuntimePlane snapshot key). E3 (the executable zero-per-metric-edit proof) is gated on G1 substrate. No impl PR until the Chief sequences E1/E2.

## Decision

Declare `RuntimePlane` as a first-class, explicit data-plane reference, and converge the evaluation read/write path onto a single plane-parametric guarded acquisition surface that resolves `plane → (root, identity predicate, role)` and runs the existing `runGuardedPlaneTx` core. The demo plane stays guarded-only (no raw handle, ever). This acquisition is the plane-parametric form of the seam migration's terminal `run` surface — E0 does not fight the seam, it sets the shape the seam shrinks toward.

Realizes DEC-89db41 (decided). Design act: DEC-c48b0f. Repair location: B (declare the plane reference) + C (bind the demo acquisition). Authority: G0 verdict (artifacts/architect/G0-plane-agnostic-evaluator-verdict-2026-10-27.md, GO Option A). Full draft body: artifacts/architect/DRAFT-ADR-E0-runtime-plane-eval-read-path-2026-10-27.md.

THE DECLARED REFERENCE (Invariant IV — explicit, not implicit):
  type RuntimePlane =
    | { readonly kind: 'tenant'; readonly dbName: string }  // tbc_{slug}, resolved from x-tenant-id / CLS
    | { readonly kind: 'demo' };                            // the one demo world (DEMO_DATABASE_URL)
Today the plane reference is implicit: every eval stage assumes tenant and builds `tbc_${slug}` inline, or reads the tenant handle from CLS with no plane at all. Making the reference explicit is the design act.

THE ONE GUARDED ACQUISITION SURFACE:
  interface PlaneConnection {
    run<T>(plane: RuntimePlane, mode: TxMode, fn: (tx: GuardedPlaneTx) => Promise<T>): Promise<T>;
  }
- plane.kind === 'tenant' delegates to the existing TenantConnectionService.run(plane.dbName, mode, fn) (identity assertRuntimeSession, role TENANT_RUNTIME_ROLE, tenant search_path) — byte-identical to the tenant plane today once a caller is on run(...).
- plane.kind === 'demo' delegates to the existing DemoConnectionService.run(mode, fn) (identity assertDemoRuntimeSession, role DEMO_RUNTIME_ROLE, search_path=demo).
Both already bottom out in runGuardedPlaneTx. E0 adds ONLY the plane→(root, identity) selection + the explicit RuntimePlane reference. No new guard logic, no new transaction control, no new identity SQL.

RESOLUTION (Chief-confirmed form a+b): (a) explicit parameter as primary — RuntimePlane threaded into the evaluation call as a declared input of the run context (tenant passes { kind:'tenant', dbName } resolved from x-tenant-id as today; demo passes { kind:'demo' }); (b) request-scoped DataPlaneEntry = { run(mode, fn) } convenience that generalizes the frozen demoDataEntry + TenantDataProvider pattern, giving both planes the identical { run(mode, fn) } shape and eliminating the raw-handle asymmetry.

HARD CONSTRAINTS (carried from DEC-89db41 + the seam):
1. No raw demo handle — demo exposes only run(mode, fn); enforced by the seam's zero-tolerance demo block (d575-tenant-tx-seam.spec.ts:193-227).
2. Both RT(plane) first-statement identity guards preserved — selection chooses the predicate, never skips it.
3. Dovetails the seam, does not fork it — E1 moving eval-path callers off forTenantData/raw token is the continuation of the seam's shrink-to-empty; the only change is the target run is plane-parametric. No second migration, no parallel surface.
4. No change to the evaluator core or the spec loader — governed-metric-runtime.ts, GovernedMetricEvaluationService, MetricSpecLoader, CONTROL_PLANE_DB untouched; plane-selection lives strictly in the data-plane acquisition layer. Zero per-metric change.

Option B (a demo-specific evaluation path) is REJECTED — by DEC-89db41 (rejects the tenant-hinge shape) and by the Foundation hard rule (a demo shim at repair-location D would be lower-layer compensation for a missing upper-layer declaration at B/C).
