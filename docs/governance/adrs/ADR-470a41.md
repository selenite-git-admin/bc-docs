# E0: RuntimePlane on the evaluation read path + plane-aware guarded data-plane acquisition

## Review history

- **Codex gen-2dec2a-01 (round 1 of 2): CHANGES REQUIRED — Finding 1 (blocking design contradiction).** The original draft claimed the evaluator orchestration was untouched while requiring an explicit plane at evaluation entry; those conflict, because the run act keys on `tenantSlug` end-to-end and a plane confined to connection acquisition cannot route the declared demo plane through the run/proof. **This revision resolves Finding 1** (the run-context plane declaration below), verified at source by the author at bc-core `f52bca2a`. Codex confirmed: (a) plane selection at guarded acquisition is the right DB boundary and the pure runtime stays agnostic; (b) the shrink-only seam is the right E1 register, with the zero-demo rule retained; (c) Invariant IV needs the plane AND consumed object versions bound into lineage; (d) B+C is the sound Foundation location. E1/E2 stay unbuilt.

## Context

DEC-89db41 generalized D575's single hard-coded `tenant` runtime plane to a declared set RuntimePlane ∈ {tenant, demo} AT THE CONNECTION/ISOLATION LAYER, and that layer is built and served (DemoConnectionService + demoDataEntry + the demo identity predicate exist). G0 found, and the Chief verified at source, that the generalization has NOT reached the EVALUATION READ PATH: every stage that acquires a data handle to read canonical facts / write a snapshot is still hardcoded to the tenant plane, and the demo plane is wired into the module but referenced by zero chain files. This ADR decides how the eval read/write path acquires its data plane so a metric evaluates against the demo plane exactly as against a tenant — consuming declared concepts, not raw fact shape, with no per-metric fact-shape coupling (G0's GO-A premise).

Verified at source (bc-core @ f52bca2a; the author re-read the run-context seam for Finding 1):
- One guarded core already serves both planes: runGuardedPlaneTx(root, mode, fn, assertIdentity) (tenant-tx-runner.ts:71) — BEGIN read only|read write → assertIdentity(raw) as the FIRST statement → fenced Drizzle handle → COMMIT iff fn resolves. runGuardedTenantTx (:103) and runGuardedDemoTx (demo-tx-runner.ts:31) are thin wrappers differing only in (root, assertIdentity). The identity judge runtimeIdentityViolations(row, role) is already role-parameterised; the demo predicate reuses it.
- The two acquisition surfaces are NOT shape-symmetric yet: TENANT_DATA_DB hands a raw request-scoped handle (deprecated D575 W6-U5), guarded replacement TenantConnectionService.run(dbName, mode, fn) exists (:105); DEMO_DATA_DB is a frozen guarded { run(mode, fn) } with no raw handle — the demo plane is already at the terminal shape.
- A seam migration is actively erasing the asymmetry: d575-tenant-tx-seam.spec.ts is a shrink-only register (baselines forTenantData=15, tenantDataToken=25, rawTenantConnection=0; serve-move requires all three empty; demo describe-block zero-tolerance, no baseline). E0 sets the shape the seam shrinks toward.
- The PURE evaluator is plane-agnostic already (G0 re-confirmed): governed-metric-runtime.ts is pure/no-DB; the spec + bindings load from CONTROL_PLANE_DB; once facts are canonical the computation is declaration-driven. **This stays unchanged — the per-metric definitions too.**
- **THE RUN-CONTEXT GAP (Finding 1, verified at f52bca2a).** The run ACT, distinct from the pure computation, keys on `tenantSlug` end-to-end: `GovernedEvaluationInput` carries only `tenantSlug` (governed-metric-evaluation.service.ts:181 — comment "routed to tbc_{slug} by the run repo + persistence adapter"); `GovernedMetricEvaluationService.evaluate` threads that slug into `runRepo.openRun`, `runRepo.finalizeRun` (deferral/refusal/failure paths) and `persistence.commitEvaluation` (:307-434, :356-360, :375-434); `MetricRunProgressionRepository.db(tenantSlug)` builds `tbc_${tenantSlug}` for open and finalize via the deprecated `forTenantData` (progression/metric-run-progression.repository.ts:73, :79, :103); the persistence adapter builds `tbc_${commit.tenantSlug}` and, in ONE transaction, writes the metric_evaluation record + fact.ms_* snapshot rows + the governed proof AND finalizes the run (boundary/governed-metric-persistence.adapter.ts:203, :210-247). **Consequence:** a plane selector confined to connection acquisition cannot carry the declared demo reference through this act — a demo candidate could be paired with a tenant run/proof, or the demo path could be unreachable. The plane must be declared in the run context, not inferred at the handle.
- **Background act, no request-scoped context (Finding 1, point 3).** Governed evaluation is a schedule/event-triggered BACKGROUND act; the run repository header states explicitly there is "no request-scoped tenant context" and it routes by explicit slug (progression/metric-run-progression.repository.ts:10-14). So the plane cannot be read from request CLS — it must be a declared input of the evaluation run request.

FOUNDATION CHECK (architectural change — gate applies, DEC-79b62f):
1. Why this location (B+C)? The gap is a missing declaration — the data plane is an implicit tenant assumption; RuntimePlane declares it (B) and binds the demo acquisition (C). Matches DEC-89db41's own repair-location naming.
2. Why not an upper layer? A/B above are specified: DEC-89db41 already declared RuntimePlane ∈ {tenant, demo} at the contract level; E0 is the C/D realization of an existing declaration, not compensation for a missing one.
3. Why not a lower layer? A lower-layer fix would be Option B — a demo-specific eval path at repair-location D. That is the forbidden lower-layer compensation and is rejected.
4. Design act or execution act (DEC-c48b0f)? Design act — a declaration (RuntimePlane as an explicit reference in the run context + the plane-parametric acquisition contract + the same-plane lineage binding), not a detector/net.
Invariant IV (references are explicit): satisfied ONLY when the act binds BOTH the selected plane AND the consumed object versions into its lineage. `tenantSlug` alone is insufficient for the demo plane. The data plane moves from an implicit `tbc_${slug}` assumption to a declared, immutable RuntimePlane reference threaded explicitly through the whole act, with no implicit demo default anywhere. No other invariant is touched (no meaning re-evaluation, no ordering change, no mutation of state, reads still never trigger evaluation).

SEQUENCING (Chief-held, nothing live): E0 ADR proposed → operator ratifies proposed→decided via a recorded desk grant → Chief sequences E1 (move the eval-path callers onto the plane-parametric guarded surface, riding the seam) + E2 (plane-aware persistence + run-context plane threading, preserving the single atomic boundary). E3 (the executable zero-per-metric-edit proof) is gated on G1 substrate. No impl PR until the Chief sequences E1/E2.

## Decision

Declare `RuntimePlane` as a first-class, explicit, **immutable reference carried in the evaluation RUN CONTEXT**, and converge the data-plane acquisition onto a single plane-parametric guarded surface that resolves `plane → (root, identity predicate, role)` and runs the existing `runGuardedPlaneTx` core. The plane is **selected once, at the run context, and carried consistently through candidate acquisition → run open/finalize → persistence → emitted proof**, with a **fail-closed same-plane check** (the act refuses if the candidate plane, the run plane and the proof plane are not identical). The demo plane stays guarded-only (no raw handle, ever). Acquisition-layer selection is the right DB boundary; the plane does not ORIGINATE there — it originates as a declared input of the run.

Realizes DEC-89db41 (decided). Design act: DEC-c48b0f. Repair location: B (declare the plane reference) + C (bind the demo acquisition). Authority: G0 verdict (artifacts/architect/G0-plane-agnostic-evaluator-verdict-2026-10-27.md, GO Option A). Full draft body: artifacts/architect/DRAFT-ADR-E0-runtime-plane-eval-read-path-2026-10-27.md.

### The declared reference (Invariant IV — explicit, not implicit)

    type RuntimePlane =
      | { readonly kind: 'tenant'; readonly dbName: string }  // tbc_{slug}, resolved from x-tenant-id / CLS
      | { readonly kind: 'demo' };                            // the one demo world (DEMO_DATABASE_URL)

Today the plane reference is implicit: every eval stage assumes tenant and builds `tbc_${slug}` inline, or keys on `tenantSlug` through the run act. Making the reference explicit and immutable, and threading it through the whole act, is the design act.

### The plane lives in the run context, carried through the whole act (Finding 1 fix)

`GovernedEvaluationInput` gains one immutable `plane: RuntimePlane` (a tenant evaluation sets `{ kind:'tenant', dbName }` resolved from `x-tenant-id` exactly as `tenantSlug` is today; a demo evaluation sets `{ kind:'demo' }`). `tenantSlug` no longer solely routes the act. The RUN ORCHESTRATION threads the plane:
- `GovernedMetricEvaluationService.evaluate` passes `input.plane` to run open, to every finalize path (deferral / refusal / failure), and to the persistence commit — never a bare slug for routing.
- `MetricRunProgressionRepository.openRun`/`finalizeRun` acquire their DB by `plane` (via the plane-parametric guarded surface below), not by `tbc_${tenantSlug}`.
- The persistence adapter acquires its DB by `commit.plane` and writes the snapshot + proof + run finalize in the SAME single transaction it does today (the atomic snapshot / run-finalization / proof boundary is preserved exactly).
- **Fail-closed same-plane check:** candidate acquisition, the run, and the emitted proof must all carry one identical plane; a mismatch refuses the act (no snapshot, no proof), never silently coerces to tenant.
- **Background-act plane source:** because the run repo has no request-scoped context, the plane is a declared field of the run request supplied by the schedule/event trigger. There is NO implicit demo default and no CLS-derived demo plane.

### The one guarded acquisition surface

    interface PlaneConnection {
      run<T>(plane: RuntimePlane, mode: TxMode, fn: (tx: GuardedPlaneTx) => Promise<T>): Promise<T>;
    }

- plane.kind === 'tenant' delegates to the existing TenantConnectionService.run(plane.dbName, mode, fn) (identity assertRuntimeSession, role TENANT_RUNTIME_ROLE, tenant search_path) — byte-identical to the tenant plane today once a caller is on run(...).
- plane.kind === 'demo' delegates to the existing DemoConnectionService.run(mode, fn) (identity assertDemoRuntimeSession, role DEMO_RUNTIME_ROLE, search_path=demo).
Both already bottom out in runGuardedPlaneTx. E0 adds ONLY the plane→(root, identity) selection + the explicit RuntimePlane reference carried through the run context. No new guard logic, no new transaction control, no new identity SQL.

RESOLUTION (Chief-confirmed form a+b): (a) explicit parameter as primary — RuntimePlane is the immutable `plane` field of `GovernedEvaluationInput` / the run request, threaded end-to-end; (b) request-scoped DataPlaneEntry = { run(mode, fn) } convenience that generalizes the frozen demoDataEntry + TenantDataProvider pattern for the request-scoped (non-background) callers, giving both planes the identical { run(mode, fn) } shape and eliminating the raw-handle asymmetry. The background run act uses (a) — never a request-scoped source.

### Hard constraints (carried from DEC-89db41 + the seam; sharpened by Finding 1)

1. No raw demo handle — demo exposes only run(mode, fn); enforced by the seam's zero-tolerance demo block (d575-tenant-tx-seam.spec.ts:193-227).
2. Both RT(plane) first-statement identity guards preserved — selection chooses the predicate, never skips it.
3. Dovetails the seam, does not fork it — E1 moving eval-path callers off forTenantData/raw token (incl. the run repo's `forTenantData` and the persistence adapter's) onto the plane-parametric `run(...)` is the continuation of the seam's shrink-to-empty; the only change is the target run is plane-parametric. No second migration, no parallel demo evaluation path.
4. **Scope of "untouched" corrected (Finding 1).** The PURE evaluator (governed-metric-runtime.ts) and the per-metric metric definitions stay UNCHANGED. The RUN ORCHESTRATION — `GovernedEvaluationInput` / `GovernedMetricEvaluationService`, `MetricRunProgressionRepository`, and the persistence adapter — MUST thread the plane; those orchestration/port changes are explicitly PERMITTED by this declaration (they are E0's core, not a downstream E2 note). `CONTROL_PLANE_DB` and `MetricSpecLoader` remain untouched.
5. **Single atomic boundary preserved.** E2's plane-aware persistence/schema work must keep the snapshot write, run finalization and proof emission in ONE transaction (as today). No split, no two-phase.
6. **Lineage binds plane + object versions.** Every emitted act binds the selected plane AND the consumed canonical-object versions into its lineage (Invariant IV); `tenantSlug` alone is not a sufficient reference for the demo plane.

Option B (a demo-specific evaluation path) is REJECTED — by DEC-89db41 (rejects the tenant-hinge shape) and by the Foundation hard rule (a demo shim at repair-location D would be lower-layer compensation for a missing upper-layer declaration at B/C).

## Consequences / sizing

- **In E0 (this ADR, DESIGN ONLY):** declare `RuntimePlane`; declare the immutable `plane` in the run context + the end-to-end threading + the fail-closed same-plane check + the background-act plane source + the lineage binding; declare the `PlaneConnection.run(plane, mode, fn)` selector over the two existing services. Explicitly permit the orchestration/port changes in §"Hard constraints" #4.
- **E1 (later, Chief-sequenced):** move the eval-path callers — including `MetricRunProgressionRepository` and the persistence adapter off `forTenantData`/raw token — onto `planeConnection.run(plane, mode, fn)`, shrinking the seam baselines toward empty and retaining the zero-demo rule.
- **E2 (later):** the plane-aware persistence commit keyed on `commit.plane` (not `commit.tenantSlug`), preserving the single atomic snapshot / run-finalization / proof boundary.
- **E3 (gated on G1):** the executable zero-per-metric-edit proof — one primary evaluated on the demo plane with no per-metric change; G1 stands up the empty demo schema (DemoDataSchema is Record<string, never> today).
- **Negative space:** no raw demo handle; no change to the pure runtime, the per-metric definitions, the spec loader or CONTROL_PLANE_DB; no new guard/identity logic; no implicit demo default; no migration opened (G1's separate operator-gated DBCP).

**Nothing in this ADR is a live act, a migration, or an impl PR. It is a declaration (status=proposed); the operator ratifies proposed→decided via a recorded desk grant byte-bound to the PR head.**
