# As-of schedule declared from the Metric Contract: aggregate_as_of admitted to the MC grammar with a hashed schedule declaration, a pinned event-grain CO, dual proof inputs, and an exact kernel

## Context

The decision rests on what the served code at bc-core 309b9da4 shows:
- The aggregate_as_of node and its guards exist (formula-execution.engine.ts:738-790; governed-metric-runtime.ts:60-80, 397-506), but no MC can declare it: NODE_KINDS excludes it.
- Nothing assembles a ScheduleDescriptor from an MC.
- Nothing sources scheduleEvents.
- Live, 0 MCVs use it.
- The served numeric profile is scaled-decimal-int-v1, yet the as-of kernel and signedRow accept only JS numbers. So the path refuses every exact-decimal row, and a Number() coercion would make an unlabelled binary64 claim.
- demo.metric_proof_input is unique per pin, so the second input is refused.
- Chain status and the fingerprint key the CC on the grain entity only, so the event CC sits outside the verdict.

Foundation gate (DEC-79b62f). This is a design act: a missing declaration is named, not netted.
- Locations: B (grammar), C (binding), D (runtime and kernel). The upper layer is specified: the meaning of concept 9e5423e0 already requires derivation from the dated legs.
- Signs and legs are declared in the hashed MC so meaning lives in contract identity (Inv I/IV).
- The value is emitted from observed dated legs at evaluation, not read from a stored residual (Inv VI). This is the capability that will let NC-626ec7 close. The ADR itself closes nothing (see Boundary).
- Reads never evaluate.
- Co-verdict: Architect-lane unit SES-8a62cb for Chief SES-7decb4; memo artifacts/chief/COVERDICT-architect-ar-balance-fork-A-packet-2026-11-11.md.

## Decision

Extend DEC-c741a3 (decided; not superseded). DEC-c741a3 declared the evaluator's P-aware signed as-of aggregate, but left the schedule's admission and declaration as future work. This ADR declares that path. Eight parts:

(1) GRAMMAR (B). The MC formula grammar admits kind aggregate_as_of {op: sum, operand: variable_ref, asof_role: reporting_point, schedule: {anchor_amount_role, anchor_date_role, anchor_sign in {-1, +1}, invoice_key_role, event_date_role, event_legs: [{key_role, amount_role, sign in {-1, +1}}]}}.
- The schedule object is canonicalized and hashed into formula_intent_hash. The anchor sign, every leg sign and every leg are MC identity: changing any of them changes the hash.
- anchor_sign is DECLARED per metric, never defaulted, and no fixed +1 rule is allowed. Its value is whatever makes the metric's declared meaning true for the bound anchor amount. The AR outstanding consumer declares +1 on the signed receivable gross. An AP payable consumer whose anchor amount is bound in the opposite convention declares -1 (signs flipped against AR). The AP mirror is a declaration, not a code branch, and the proof vectors in (8) demonstrate it.
- Validation at canonicalization (refusal, never repair):
  - anchor_sign and each leg sign must be present and exactly the integer -1 or +1 (0, a fraction, a string or an absent value refuses);
  - event_legs must be non-empty;
  - every named role must be a non-blank role code;
  - two legs may not repeat the same (key_role, amount_role) pair.
- No sign or leg is inferred from role-code spelling or hard-coded in the assembler or the runtime.

(2) ASSEMBLY (C/D). The spec assembler resolves the named roles to CO fields and builds the ScheduleDescriptor from the declaration.
- The descriptor's anchorSign comes from the declared anchor_sign, and each leg sign from its declared sign. Both are value-changing, so the assembler has no default for either.
- The descriptor gains a separate invoice key field and per-leg {keyField, amountField, sign}. The single-field form is the one-leg degenerate case.
- A role that is named but unbound, or bound on an entity with no single active CC, refuses.
- Bindings stay ordinary input rows; there is no mcf DDL.

(3) GUARDS. Every existing fail-closed guard is preserved and applied per leg:
- an omitted event source refuses; a sourced-but-empty list is allowed;
- the currency policy must be document_currency or single_currency_required;
- every leg key is a non-blank string;
- invoice keys are unique;
- invoice currency is present;
- a missing or invalid date refuses;
- a non-finite or non-exact amount refuses.
The run records matched and unmatched leg counts as emitted evidence.

(4) SOURCING (D). The evaluation orchestrator and the demo commit source the event-grain CO on the same plane, world binding and SO admission version as the grain CO, at the pinned coordinate. An absent source refuses.

(5) EVIDENCE (Inv IV/VI). The proof binds both inputs:
- demo.metric_proof_input carries one row per input role (grain, schedule_event), unique per pin and role;
- each row carries the CO digest, row count and lineage sha.
- The live constraint ck_metric_proof_input_rows (co_row_count > 0) contradicts the sourced-but-empty event list that (3) allows. The DB act must reconcile them explicitly:
  - the grain role keeps co_row_count > 0;
  - the schedule_event role allows co_row_count >= 0;
  - an empty event source is still a recorded, pinned input (a digest of the empty set and its lineage sha), never an absent row.
This is a bc-db forward migration under the operator's DB-yes.

(6) CHAIN STATUS AND FINGERPRINT.
- mcv_chain_status adds schedule_cc_active: exactly one active CC for the schedule's event entity.
- The dependency fingerprint basis (and its DB-trigger mirror) includes the event CC version, under a basis version bump, so a re-cut event CC stales the verdict.

(7) NUMERIC DOMAIN (DEC-c4619b).
- Under scaled-decimal-int-v1, schedule amounts enter as exact decimal strings, and v3 sums aggregate_as_of with the scaled-decimal BigInt kernel: the same semantics, no labelled downgrade.
- binary64-v1 keeps the v2 kernel.
- Red-first on a vector where binary64 and exact sums differ.

(8) PROOF VECTORS (required of the later engine act). The engine PR proves the formula identity and the value with:
- positive AND negative anchor vectors (anchor_sign +1 and -1);
- positive AND negative leg vectors (debit leg -1, credit leg +1, and the AP mirror);
- for each vector, flipping that one sign changes formula_intent_hash and changes the computed value, and an absent or invalid sign refuses.
- Runtime-authority pins and auditor republication are re-checked on the engine lane.

Scope: general for residual-as-of-P and aging in AR, with AP as the declared sign mirror (the anchor and leg signs flipped against AR, all declared in the MC). The first consumer is the ar_balance_outstanding successor MC (NC-626ec7). Lane: platform for the engine PRs (Codex). The metric authoring and lifecycle acts stay in the metric lane under ead781aa.

Boundary. This ADR is a design act: it declares a capability and the obligations of the later engine and DB acts. It does not itself close NC-626ec7. The NC closes only when the served successor metric is realized from the dated legs, carries a passing proof (R1 and its pin uid), and no binding to the stored-residual column remains.
