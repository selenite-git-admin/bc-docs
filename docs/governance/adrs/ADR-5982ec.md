# The point_in_time family reshape: re-declare each member's true temporal meaning (shape and definition), grouped by target shape

**Status:** proposed. Successor to DEC-d0b66a (decided), which it applies — it does **not** supersede it. Author: Architect SES-b9b0ef. Grounded at bc-core `origin/main` `18ed19e4` and bc-docs `origin/main` `da90d32b`, and the live `bc_platform_dev` MCF substrate, 2026-10-07. The operator decides this ADR; it authorizes no write or evaluation act.

## Context

DEC-d0b66a decided, for the `point_in_time` shape, that it resolves to **identity** (no gate-level date basis and no runtime period/snapshot selection), that its directory generator **over-claims** an as-of runtime semantic the evaluator does not implement, that its members are therefore **not auto-clean**, and (Decision 5/6) that giving a member "the state at a reporting point" is a **re-shape** to `as_of`/`cumulative_to_date` and is **its own design act**. DEC-d0b66a settled the shape's semantics on a single-member finding. This ADR carries that decision across the **whole `point_in_time` family** as the design act Decision 6 anticipated.

**The substrate population (live `bc_platform_dev`, 2026-10-07).** `mcf.metric_contract` holds **49** non-archived `point_in_time` contracts. These are **27 distinct base concepts** plus **22 `__tacorr_*` duplicate variants** (the C-FX-8 row-stamping temporal-anchor correction from `metric-directory.service.ts:289-302`; one companion for each stock and each flow — the 5 counts carry none). The 27 base concepts are **6 stocks** (5 on the GL Account grain + 1 `total_standard_cost` on the Product grain) **+ 5 counts + 16 flows**. (Two further members Metric triaged alongside this family — `write_off_amount`, `customer_invoice_line_item_count` — carry the `none` shape, and `total_cash_balance` is already `as_of`; they are related defects dispositioned below, but they are not `point_in_time`.)

**The defect is a meaning-fidelity defect (Invariant I — meaning is evaluated once, and must be evaluated as what it means).** The 16 flows are **named** as flows but **defined** as as-of stock snapshots. Verbatim from the current substrate:

- `operating_revenue_amount` (a P&L flow): *"As-of (point-in-time) snapshot balance (sum) of the GL Account grain filtered to … 'operating_revenue' …, point_in_time as-of balance date (a stored balance/stock read as-of the reporting date …)".*
- `financing_asset_movement` (a cash-flow movement): *"As-of (point-in-time) snapshot balance (sum) … as-of balance date (a stored balance/stock read as-of …)".*
- `change_in_current_assets` (a period delta): *"As-of (point-in-time) snapshot balance (sum) …".*

A flow's meaning is a quantity **accrued over a period**; defining it as a stock **read at one date** declares a different meaning than the one the member names and the one a reader expects. Reshaping only the gate shape and leaving the definition wording in place would leave Invariant I violated at the declaration.

**How each target shape selects at runtime (bc-core `18ed19e4`, `src/boundary/select-by-gate.ts` dispatch + the caller).** Every shape this ADR reshapes to performs real governed selection today; only the degenerate point shapes do not:

- **`as_of` — real gate selection, two governed modes.** `selectByGate` dispatches `as_of` to one of two modes. The **default (state) mode** (`selectAsOf`, DEC-c4c742) selects items **open/closed at P** by a declared `closing_field` + `anchor_field` (optionally an age band). The **`latest_observation` mode** (`selectLatestObservation`, DEC-d3492b / D518) groups candidates by a declared **series key** and resolves **exactly the maximum stamped anchor ≤ P per series member** (ties by the declared tiebreak, then stable ref order; null/future anchors excluded; no fabricated zeros). `package-signature.service.ts` requires `selection: latest_observation` + `anchor_field` + non-empty `series_key_fields` and **forbids** `closing_field` for that mode; the default mode requires `closing_field` + `anchor_field`. Both modes report `selective: true`.
- **`cumulative_to_date` — real gate selection.** `selectByGate` dispatches it to `selectCumulative`, which requires the evaluation period ordinal (`(fiscal_year, period_number)`; fails closed without it) and resolves the stamped ordinals from the scope start (`fiscal_year` or `all_time`/inception) through P, reporting `selective: true`. The gate spec is built by `gate-spec-from-substrate.ts` with an `all_time` or `fiscal_year` scope.
- **`period_aggregate` — selects via the caller.** The gate resolves `period_aggregate` to identity, but the caller period-scopes it: `metric-evaluation-orchestrator.service.ts:289` sets `periodScoped` for `period_aggregate`, and `co-candidate-reader.ts:20-26,130-138` filters candidates to the single target `fiscal_period` (or a declared anchor range).
- **`point_in_time` / `instantaneous` — identity, NOT selected.** They resolve to identity and report `selective: false`; neither the gate nor the caller scopes them. This is the degenerate behaviour this ADR repairs by reshaping away from `point_in_time`.

**The same concepts, done right — the reference pattern.** The `cumulative_to_date` family on the **journal-entry-line grain** (11 contracts, active) expresses the balance-sheet and earnings concepts with the **correct shape, the correct definition, and correct runtime selection** (`selectCumulative`): e.g. `current_asset_balance`, `total_asset_balance`, `current_liability_balance`, `recorded_equity_balance`, `non_current_liability_balance`, `earnings_to_date`, `receivable_control_balance` = *"the sum of amount_input, the posted amount of each journal-entry line …, over [period to date]"* — a real period-ordinal row selection. It is the pattern the stock reshape targets, and the evidence the `point_in_time` GL-Account-grain stocks are wrong-shaped duplicates of concepts this family already states and evaluates correctly (see Decision 2, stocks).

**Active exposure.** Of the 27 concepts, **6 are producing today**: the 5 counts (`gl_account_count`, `financing_/investing_/operating_gl_account_count`, `cost_center_count`) and `current_liabilities` (via its active `__tacorr` variant) each have an active current version. Their grains' canonical contracts are active, so the evaluator runs them now as `point_in_time` = identity — a **date-less current snapshot presented as an as-of value** (worse than non-producing: it looks authoritative). The remaining 21 concepts have **no current version** (in-flight / `audit_pending`); they are **latent** exposures that become live on activation.

**Why an ADR, not a directory-clean or an evaluator patch.** The declared meaning is wrong at the contract layer. Correcting the directory classification (read model, F) or adding an evaluator selection (D) without first re-declaring the member's true shape and definition would be lower-layer compensation for an upper-layer declaration gap — forbidden by DEC-c48b0f and the Invariants. The faithful repair is a declaration act at **repair location B** (contract semantics).

## Decision

1. **The reshape target is the member's economic meaning, not its current (wrong) shape.** Each member is re-declared to the shape that evaluates its true meaning once, correctly (Invariant I). The current `point_in_time` shape is retained for a member only where identity selection already equals its intended value (a current-state read whose grain yields a single-reporting-date candidate set) — per DEC-d0b66a Decision 5.

2. **Per-member disposition, grouped by target shape.** Metric's per-member triage (first-hand, MSG-e6764c) is the authority for each member's target; this ADR records the target-shape doctrine and the groupings. **For every member reshaped to `as_of`, Metric's disposition must name the intended `as_of` mode** (default state vs `latest_observation`), **the series or item identity, the available anchor/closing fields, and the tie behaviour** — a shape-only `as_of` instruction is ambiguous (it could select every still-open historical row, count observations rather than entities, or fail package-signature validation). Where the grain already presents exactly one eligible row per entity as of P, that substrate precondition is stated explicitly.

   - **Stocks (6) → `as_of`** (5 GL Account grain: `current_assets`, `current_liabilities`, `total_assets`, `total_equity`, `total_liabilities`; 1 Product grain: `total_standard_cost`). A balance-sheet stock is the value **at** a reporting date; its faithful shape is `as_of`. The **mode depends on the source the grain offers**: if the grain carries a stored per-entity balance snapshot stamped with a balance-date anchor, the target is **`as_of latest_observation`** (series key = the entity identity; max anchor ≤ P per series; the formula then aggregates across the series). If the only faithful source is a sum of journal-entry lines to date, the correct shape is **`cumulative_to_date`** — which is the **supersession** case below. **Sub-decision (duplicate vs distinct grain):** each GL-Account-grain stock has an already-declared, correctly-evaluating counterpart in the `cumulative_to_date` JEL family (`current_assets` ↔ `current_asset_balance`, etc.). Where the two express the **same** economic concept, the faithful repair is **supersession by the existing JEL member** (abandon the duplicate; soft-archive the parent, never mutate the version — Invariant III), not a parallel reshape. Where a distinct stored-balance grain read is genuinely intended, the `as_of` reshape (with its declared mode) applies. **Metric confirms, per stock, duplicate-vs-distinct-grain and — if distinct — the `as_of` mode and fields, before the reshape executes.**
   - **Counts (5) → `as_of` count** (4 GL Account grain: `gl_account_count`, `financing_/investing_/operating_gl_account_count`; 1 Cost Center grain: `cost_center_count`). A count of a grain's **entities as of** a reporting date is a count of the latest observation per entity ≤ P (`as_of latest_observation`, series key = entity identity, then COUNT on a row-count basis — not COUNT_DISTINCT, and **not** a count of observations across periods). These 5 are the members **actively producing today** (Context, active exposure).
   - **Flows (16) → `period_aggregate` or `cumulative_to_date` (never `as_of`).** The 8 P&L amounts (`operating_revenue_amount`, `cost_of_sales_amount`, `operating_expense_amount`, `other_expense_amount`, `other_income_amount`, `interest_expense_amount`, `tax_expense_amount`, `depreciation_amortization_amount`); the 2 period deltas (`change_in_current_assets`, `change_in_current_liabilities`); the 6 cash-flow movements (`financing_/investing_` × `asset_/equity_/liability_movement`). The **per-member choice between period (`period_aggregate`) and year-to-date (`cumulative_to_date`) is Metric's call**, by the member's intended meaning. Two notes: (a) the 2 `change_in_*` deltas are **differences of two balances** (balance(end of P) − balance(start of P)); their reshaped declaration must **bind both endpoints** and express the difference, and must **not** silently become a `period_aggregate` of raw single-period amounts; (b) a `period_aggregate` target declares its period basis — a declared `anchor_field` (anchor-range scope) **or** the canonical stamped `fiscal_period` label (the default); `anchor_field` is optional and the per-member declaration chooses which basis is intended.
   - **Related `none`-shape defects (2) → `period_aggregate`.** `write_off_amount` (Customer Invoice grain); `customer_invoice_line_item_count` (Customer Invoice Line Item grain). Not `point_in_time`, but the same meaning-fidelity class: a shapeless flow must be declared `period_aggregate` with its period basis.
   - **Questionable (1): `total_cash_balance`** (already `as_of`, with a NULL closing field). Its `as_of` mode must be made explicit: declare `latest_observation` (series key + anchor, no closing field) or the default mode (closing + anchor). Do not leave the mode-determining fields silently null.
   - **`__tacorr` variants.** The disposition attaches to the **concept**: a base member and its `__tacorr_*` companion are reshaped together (where `current_liabilities` carries its meaning on the active `__tacorr` variant, that variant is the one reshaped).

3. **Name↔definition fidelity is corrected in the same act.** For every flow (and the `none`-shape defects), the **definition wording is re-authored** to its true flow/cumulative meaning in the same reshape; the as-of-snapshot phrasing is removed. Correcting the shape while leaving the definition describing an as-of stock read would record a new version whose declared meaning still contradicts its shape (Invariant I). Shape and definition are re-declared as one design act per member.

4. **The reshape is gated on the per-member declaration and the write-lane halt — not on the `point_in_time` predicate (TSK-36440f).** Grounded at bc-core `18ed19e4`: every target shape this ADR reshapes to — `as_of` (both modes), `cumulative_to_date`, and `period_aggregate` — performs real governed selection **today** (Context). So each reshape is executable once (i) the standing write-lane halt lifts and (ii) the member's declaration is complete (shape + `as_of` mode + series/item identity + anchor/closing fields, or the flow's period basis). **No reshape target depends on TSK-36440f.** TSK-36440f (the per-input period predicate for `point_in_time`) is the **alternative** repair DEC-d0b66a Decision 6 names — building `point_in_time`'s own selection so a member can stay `point_in_time` — and reshaping to a shape that already selects makes it unnecessary for the reshaped members. TSK-36440f remains relevant only for any member deliberately **kept** `point_in_time`. This ADR **declares** the targets; it **builds nothing** and closes no gap (consistent with DEC-d0b66a Decision 7).

5. **Active exposure is recorded, not latent.** The 6 producing members (5 counts + `current_liabilities` via `__tacorr`) emit a date-less `point_in_time`=identity snapshot presented as an as-of value **today**. This is recorded as an **active meaning-fidelity exposure** (risk RSK-2ff5b1 / the DEC-d0b66a wrong-data risk). Until the reshape executes, they remain exposed; the ADR does not by itself remediate them. The other 21 concepts are latent (no current version) and become exposures on activation. **No related cross-family exposure:** the active `cumulative_to_date` JEL reference family selects correctly at runtime (`selectCumulative`), so it is both declared-right and evaluated-right — the earlier round-2 draft wrongly read it as runtime-degenerate from a stale selector module-header comment; the implementation and its tests (`select-by-gate.spec.ts`) select across the scope and fail closed without the period ordinal.

6. **Foundation.** Repair **location B** (contract semantics — the declared temporal meaning). This is a **design act** (a wrong/missing declaration of true meaning), not a detector: per DEC-c48b0f item 5, an execution-plane detector is a net, not a fix, so correcting the gate's refusal would not repair the declaration. No lower-layer compensation: the directory must not clean these members on "`point_in_time` = identity." Invariant III holds throughout: reshape mints new versions / supersedes; it never mutates an existing version row, and abandonment soft-archives the parent.
