# Feed-epoch supersession: successor enforcement feed after transport-ledger divergence (enforcement-2 cut)

## Context

Canary B's signed packet (enforcement-1 seq 3/4, prior digest 2e77f3a7...) could not be published: audit_execution.append_outbound_feed_publication anchors on the latest outbound_feed_publication row, and that table holds only pre-wipe pilot rows (seq 4-81) from the corpus destroyed in the operator-authorized greenfield wipe - the wipe was one-sided, so the auditor transport ledger was never re-anchored. The ledger and the signed chain had already diverged at canary A (delivered via repo files, never appended to the ledger). Alternatives rejected: re-signing canary B as seq 82/83 is impossible (the platform import verifier enforces continuity against its imported head, seq 2) and would graft the dead epoch onto the live chain; deleting rows 4-81 is history surgery the system exists to prevent; a standing quarantine/epoch layer is new machinery for a one-time recovery and fails the structural-recurrence test. The successor feed uses only proven registration paths (C11 feed re-registration was exercised 2026-07-24; the auditor bootstrap path produced the 2026-07-18 row). Cost accepted: canary B must be re-signed because feed_name is inside the signed envelopes.

## Decision

Doctrine: when an audit-exchange transport ledger and the signed feed chain diverge, the ledger is re-anchored by SUCCESSOR REGISTRATION, never by mutation. Stale ledger rows are preserved as retired-epoch evidence; nothing is deleted, no triggers are disabled, no rows are hand-inserted, and no envelope is re-signed onto a dead chain.

Applied instance (the canary-B cut): the enforcement response feed bc-external-audit.metric-audit-decision.enforcement-1 is RETIRED after its imported head (feed_sequence 2, canary A decision, envelope digest sha256:2e77f3a7986bf07d9643d5ed7a1e4a6cc5404ce13e43e739c59af8eb4ec879dd). A successor feed bc-external-audit.metric-audit-decision.enforcement-2 is registered on both sides through the EXISTING governed paths: (a) auditor-side outbound_feed_bootstrap row for enforcement-2 (genesis, next_sequence 1) whose authority_ref cites the enforcement-1 head digest and the operator authorization; (b) platform-side C1 registration imported as the control feed's next event (bc-external-audit.feed-registration.control-1 seq 2, prior digest sha256:78474caee3a1c0a1a00b3f72228a2a89773575e2e7338aeb1df4ee0bfb7f74af), using feed_registration.supersedes_registration_uid = fa3b388d-bab2-40e9-b81f-ff89010792c2; (c) canary B re-signed by the auditor as enforcement-2 seq 1/2 and republished via append_outbound_feed_publication + response_packet_outbox; (d) one reviewed bc-core PR updating ENFORCEMENT_RESPONSE_FEED in MetricAuditExchangeConsumerService to enforcement-2. The already-published canary-B request (metric-audit-request seq 2, request 650d3139) does not embed the response feed name (verified against its canonical payload) and survives the cut untouched. Stale auditor-side artifacts (outbound_feed_publication seq 4-81, 6 pre-wipe outbox rows, the 2026-07-18 enforcement-1 bootstrap row) are preserved, unreferenced by the active lane.

Line-drawing rule ratified with this decision: (1) bypasses are never acceptable; (2) if an existing governed path fits, use it - that is not new machinery; (3) NEW machinery is built only when recurrence is structural (second occurrence, or recurring by construction over an enumerable population); (4) one-time events get a decision record, not a tool. A second epoch cut, if it ever occurs, is the trigger that justifies a standing epoch/disposition layer (the option-3 design recorded in the context).
