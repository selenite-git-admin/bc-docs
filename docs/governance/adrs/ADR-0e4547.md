# Platform DB Foundation Program operating model — approval-only operator, design briefs, autonomous implementation units, auditor-gated merges

## Context

Ratified by the operator on 2026-09-09 ("ratify D1 D6 D8"). The prior de-drift task (TSK-3f52d7) ran for weeks with the operator involved turn by turn, and the mechanical burden hid the structural gaps from everyone; the operator's stated requirements were to minimize their role to program approval, avoid weeks-long ceremony, and run approved work autonomously on a non-frontier model since the build is architectural rather than a deep logical drive. The independent auditor's first requirements review confirmed the design-brief/autonomous-unit split is sufficient provided approval binds the actual scope and a machine-checkable contract, and corrected the review rule so that correction to acceptance is normal and escalation is reserved for genuine design disputes.

## Decision

Roles. Operator: approves the requirements document, each wave's one-page design brief (scope, machine-checkable acceptance criteria, gates), and any application to a live database under the Database Change Protocol; ratifies decision records. Nothing else reaches the operator. Builder: executes units against approved acceptance criteria, self-verifies every claim firsthand, produces evidence with checked-in tooling, submits exact-commit units, and performs correction-to-acceptance without operator involvement. Independent auditor (Codex via bc-auditor-app): reviews each design brief and implementation unit at an exact commit, contributes architectural omissions and risks as a platform/DB architect, and — under the operator's standing authority for documentation and record units (2026-09-09), or per-unit authority for other unit types — merges accepted heads with green CI via the App. Unit shape: each wave = a design brief (judgment-heavy; careful reasoning) plus implementation units (mechanical against the brief; may run on a capable non-frontier model). Review: one round is the target; finite implementation or evidence repairs continue until acceptance; escalation to the operator only for a genuine design dispute unresolved after two rounds. All operator-only live gates and unsafe-operation stops are retained regardless of who executes a unit. Evidence custody: committed bytes, hashed with no text conversion; exchange messages byte-identical on both mirrors; operator statements relayed verbatim without builder gloss.
