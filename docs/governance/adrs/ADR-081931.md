# Standing Claude↔Codex exchange family gen- (topic-filtered, permanent)

## Context

The operator can no longer relay between Claude (Mac) and Codex (laptop). A single standing family reuses the proven exchange protocol with no new infrastructure. Headers give topic filtering and consequence-scaled review. The per-topic open-message rule keeps the one-at-a-time discipline without making unrelated items wait. The operator chose one family over separate landing and general families (2026-09-25).

## Context

On 2026-09-25 BareCount development moved to the Mac Mini. Codex, the independent auditor, stays on the Windows laptop. Long programs already run on automated exchange families (d597, d617, d619, dbr, rte…), committed to bc-external-audit and polled by Codex. Everything else — small design questions, one-off reviews and the shared PR-landing thread — was relayed by the operator by hand between two sessions on one machine. That manual relay is no longer practical.

A fuller design (one neutral ledger repo, a CI-rung notification "doorbell", a builder/auditor roles registry) exists and is parked as TSK-861e27. This decision is its first, minimal step and does not pre-empt it.

## Decision

1. **One permanent family, `gen-`.** It carries every Claude↔Codex item that does not belong to an active program family: PR landing reviews, ADR/docs PRs, small design questions, one-off reviews, infra and DevHub items. Program families are unchanged. If a `gen-` item grows into a program, the operator may move it to its own family.

2. **Transport.** The same as the existing families: files committed to `bc-external-audit` `docs/` on `origin/main`. Claude publishes `MSG-Claude-gen-NNN-<slug>-<date>.md`; Codex answers `RESPONSE-Codex-gen-NNN-<slug>-<date>.md` (or `PROOF-`/`CLOSURE-Codex-gen-NNN-*` for executor output). `NNN` is one sequence across the whole family. Codex's polling is the delivery path; any faster nudge is an optional hint. Claude watches for new Codex commits on `origin/main`, not for a file-name pattern.

3. **Required headers.** Every `gen-` message and response starts with:
   - `Topic:` the area — infra, docs, devhub, db, security, bc-core, bc-admin, bc-portal, bc-demo, bc-infra, or a new topic named in the message;
   - `Kind:` `landing` (approve/merge a PR at an exact head), `design` (review an approach before build) or `question`;
   - `Depth:` `light` or `full` (point 5);
   - `Re:` the prior gen- number(s) this answers or continues, or `new`.
   Every message and response ends with exactly one final line `NEXT: Claude | Codex | both hold`.

4. **One open message per topic.** A message is open until Codex's response for it lands. Claude may have messages open on different topics at the same time, but never two on the same topic. Related items that are ready together are folded into one message.

5. **Depth by consequence.** `light` for docs, records, runbooks, memory-style notes and small tooling with no platform behaviour; `full` for database applies, schema, security, auth, cloud, secrets and anything that changes platform behaviour or evidence. Codex may raise a message's depth, never lower it.

6. **Authority comes only from the operator, directly.** A `gen-` message never carries authorization, and Codex never treats one as such. Merge authority, live DB applies, cloud changes and other operator-only gates are granted by the operator to Codex directly, per class or per item. By default Codex has no merge authority on `gen-`.

7. **Permanent automation.** The family is not closed by a phase close, a disposition or the words "over and out". Automation is torn down only on an explicit operator-attributed instruction or the token `TEARDOWN-AUTOMATION`.

8. **Custody.** Messages are published byte for byte from a clean checkout of `origin/main`; the publisher records the commit and SHA-256 of each file.

## Consequences

- The operator no longer relays between the two models; the operator's role on `gen-` is authorization only.
- The manual shared landing thread is retired for new items.
- The later ledger (TSK-861e27) imports `gen-` history as-is and keeps the header format.
