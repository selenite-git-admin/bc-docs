# Demo world-builder pivots to a model-driven compiler (Foundry): one typed world model, everything else a projection

## Context

No rationale recorded.

## Decision

Operator-directed redesign (2026-08-30) after two same-day scope misses (compliance segment, exports/FX) that only operator domain knowledge caught: the file-federation framework (CSVs/YAMLs/registers/UI) could not check coherence across interacting layers (scope, modules, surfaces, plans, economics, QA, UI). Decision: a single typed world model with referential integrity (SQLite working store + canonical deterministic JSON export as git truth) — scope expressed ONLY through capabilities with typed requirements; three planes separated (facts extracted from Odoo, decisions journaled with provenance, derivations recomputed); UI/RUNBOOK/QA-portfolio/build-plan become projections; the executor builds from the model and QA diffs world-as-built vs model-as-declared. This applies BareCount's own Foundation invariants to the demo-builder itself (meaning evaluated once, explicit references, immutable generations, emitted evidence). v1 landed at bc-demo sources/odoo19ee/foundry/ (SCHEMA.md + foundry.py), 14,180 objects imported from the prior artifacts with provenance intact, validator proven RED on both real incident classes (exports-USD incoherence, l10n_in_reports missing from closure). Tuning continues while working (operator). Supersedes-in-approach: the file-federation run-package remains as the model's import/export surface, no longer the authority.
