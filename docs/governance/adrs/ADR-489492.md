# W5 assembly rule — the bc-db spine is the platform schema authority; retire the docker/redesign modular↔monolith lockstep (amends DEC-591eb7)

## Context

Ratified by the operator on 2026-09-19. The Platform DB Foundation W5 cleanup wave must resolve the modular→monolith "assembly rule": how `docker/redesign/02-platform-tables.sql` (a hand-maintained monolith) relates to the modular set `docker/redesign/02-platform-tables/`. The proposed DEC-591eb7 ("Single modular SoT → generated platform monolith + CI parity gate", status *proposed*) anticipated building a generator that assembles the monolith from the modular set with a from-zero≡live/golden parity gate.

Since that proposal, the `bc-db` spine has become the ratified schema authority (DB-as-a-product; ADR-b1a286 waves executed through W1): the `bc-db` `0000` baseline reproduces the live platform schema from zero at parity fingerprint `c309ea3dee78d933ef1a043e44df9c85ed9ca5dee074924a0c3001e9e14cf3be`, and the `bc-db` from-zero **equivalence gate** already enforces exactly the from-zero≡live/golden parity guarantee DEC-591eb7 specified. The hand-maintained monolith and the modular set under `docker/redesign` have drifted and are not a 1:1 assembly; the path is a pre-`bc-db` artifact.

FR-4b of the accepted requirements requires that a change of assembled-schema authority "must name the amendment rather than replace it silently." This record is that named amendment.

## Decision

For W5, the modular→monolith assembly rule is resolved by **retirement, not a generator**. The `bc-db` `0000` baseline is the authoritative assembled platform schema; its equivalence gate provides the from-zero parity guarantee DEC-591eb7 sought. The `docker/redesign` modular↔monolith lockstep and the interim FR-4b rule end here by retirement; **no monolith generator is built**. This supersedes the proposed DEC-591eb7 and amends b1a286 clause 4 to name the `bc-db` spine as the assembled-schema authority.

Execution is gated: before removing `docker/redesign`, any remaining local-dev bootstrap that mounts `02-platform-tables.sql` is transitioned to source from the spine / the S3 golden restore (DEC-5c39ea); each removal and the directory rename execute only under the W5 wave's independent auditor review at an exact commit. Production Gate-④ remains operator-only.

## Consequences

- Schema documentation (FR-16) is generated from, or checked in CI against, the `bc-db` spine (see `bc-db docs/schema-shape.md`), not hand-maintained.
- The `docker/redesign` monolith generator described by DEC-591eb7 is not implemented; DEC-591eb7 is superseded.
- The `docker/redesign` retirement, the directory rename, and the local-bootstrap transition are W5 reviewed-retirement units, not executed by this record.
- The legacy-metric table DROP (a separate W5 concern, custody the program mandate DEC-75fc71) is unaffected by this record and remains gated on its own re-point + review + operator go-ahead.
