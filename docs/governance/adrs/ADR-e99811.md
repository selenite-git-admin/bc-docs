# A metric's expected values come from its locked reference, placed by one governed command

## Context

A metric is proven on the demo world by comparing the platform's evaluation with expected monthly values. Today those values enter as a hand-over: an answer sheet file produced outside the platform, plus a pin of the metric contract version on a world label that only the database owner can run (migration 0087 routines, EXECUTE granted to no login). No served command places a metric, and each metric needed a hand-placed pin and a hand-over.

On 2026-11-27 the owner ruled the demo world decoupled from the platform: the world has done its job of producing real-life source data (41 months), and what it answers is stored in the platform as a locked proof. Migration 0091 created the locked reference store (`mcf.reference_frozen_copy`, `mcf.locked_reference`, `mcf.locked_reference_month_value`): written once, anchored in WORM, update, delete and truncate refused, the authoring panel's login (`bc_platform_runtime`) given no access. The first rows are live (every triaged candidate as found; Customer Invoice Count as proof-ready version 2, keyed to definition c93e90ba, 41 months).

The owner then ruled "Build permanent route" (not an interim generator feeding the old answer sheet, plus a hand-placed pin per metric), and, after a red team, "The smallest permanent proof route, and two rulings", and gave the database yes for migration 0092 ("Yes, build 0092"). Rulings are in barecount-devhub, branch claude/operator-review-content, `artifacts/operator-review/DECISIONS-workflow-review.md` (commits ad2fd8ff, bd539b99, 355b3040). The design is the side-session proposal `migration-0092-PROPOSAL-2026-11-27.md` and its red team `permanent-proof-route-REDTEAM-2026-11-27.md`.

Authorities this touches:
- DEC-025bfc T4 (oracle independence): the oracle is frozen-byte, provenance-stamped, authored independently of the metric contract, and never derived from the evaluator output or the contract-generation path.
- The D2 rule: the declaration that a hand-over's expected cells are the cells of the answer sheet, read by `demo.fn_answer_sheet_cells` and enforced by the two bridge predicates `demo.fn_pin_answer_sheet_refusal` and `demo.fn_pin_handed_over_expected_cells_refusal` (migrations 0075 and 0082).
- DEC-89db41: the demo plane is reached only by its own logins, with no direct or indirect reach from the platform plane (amended for `bc_demo_prover` by DEC-b269fd; DEC-1bb88e made the demo plane a resolving plane).

## Decision

1. **Expected values come from the locked reference.** A metric version's expected monthly values are those of the proof-ready locked reference of its definition (0091). No answer sheet file hand-over is needed for a placed version. The reference feeds no evaluation; it is only compared against (Invariant I).
2. **One place door.** bc-db 0092 adds `mcf.fn_place_world_metric_version(text, uuid, uuid, text, text)`, SECURITY DEFINER, owned by `bc_schema_owner`, search_path pinned, EXECUTE to `bc_platform_runtime` only. It lives in `mcf`, so the served login needs no USAGE on schema `demo`. It calls the unchanged 0087 `demo.fn_pin_world_metric_version` (seal, state, one chain, one live version per binding at commit) and returns the pin id. A bc-core command `place-world-metric-version` (check and do, role `mcf_publisher`) wraps it; `declared_by_name` is the signed-in identity, never the request body. It replaces the parked pin doors (0090, bc-db PR 203, bc-core PR 1111 reworked); 0090 stays unused and its doors are never created.
3. **Refusals, by name, with no value in any message:** `place_argument_missing`, `place_label_absent`, `place_label_unbound`, `place_binding_not_current`, `place_version_absent`, `place_version_semver_ambiguous`, `place_definition_unrealized`, `place_reference_absent`, `place_reference_ambiguous`, `place_reference_month_not_defined`, `place_reference_currency_deferred`, `place_custody_occupied`. Every 0087 trigger still decides the pin; the command re-implements no rule.
4. **Copy at place, with an FK as the one source of truth.** In the statement that places the pin, the door writes one custody cell per locked month value into `demo.oracle_custody`: oracle value, the reference's WORM file sha256, the independent author, a custody coordinate, and a new nullable column `locked_reference_month_value_id` (foreign key to `mcf.locked_reference_month_value`, with an index). The door is the only routine that names the column, so the copied value equals the locked value by construction and is not re-checked later. Existing rows stay NULL (legacy hand-over or author cells). The oracle's custody set hash covers the WORM sha of every placed cell (Invariant VI).
5. **Three predicates accept placed cells.** `demo.fn_answer_sheet_cells`, `demo.fn_pin_answer_sheet_refusal` and `demo.fn_pin_handed_over_expected_cells_refusal` are replaced with the same signatures. A placed cell counts as handed over when the FK is present, its month is on the world's current binding (pin's input binding for the bridge; else `answer_sheet_world_mismatch`) and its reference is the chain head (else the new code `answer_sheet_reference_superseded`). The legacy hand-over legs and the custody-set hash recompute are byte for byte unchanged.
6. **The served login's single new reach.** `bc_platform_runtime` gains EXECUTE on this one routine (its G10 pin gate goes from 19 to 20). It still has no USAGE on `demo`, no privilege on any demo table, no EXECUTE on any demo routine, and no privilege on the two locked reference tables (0091's postcondition holds).
7. **Prove and bridge of a placed version are metric evaluation acts** (`demo-commit` and `demoed-bridge`) under standing grant ead781aa, with no per-metric desk grant. The database change and the engine serve still need recorded grants, once. "Certification held" covers certify and activate only; the approved-to-audit-pending move (request audit) is allowed.
8. **Not placeable yet (refused by name, owner ruling):** ratios with `not_defined` months and multi-currency metrics.
9. Rollback of 0092 is refused once any custody row carries the FK (placed proof evidence, Invariant III); otherwise it restores the three predicate bodies byte for byte. 0091's rollback runs only after 0092's.

## What this amends and extends

- **Amends DEC-025bfc T4.** The oracle is still frozen-byte, provenance-stamped and not derived from the evaluator output or the contract path. Its independence is now carried by the locked reference: written once, WORM-anchored, outside the authoring panel's reach, with its author family recorded and the platform's metric contract as the independent second working. The custody row names the WORM file sha and the month value row, instead of a hand-delivered file.
- **Amends the D2 rule** (the answer sheet declaration). Expected cells reach custody by placement from the locked reference, and the answer-sheet predicates accept them on the three tests of point 5, instead of only a handed-over file.
- **Extends DEC-89db41** by one named routine. The demo plane stays otherwise reached only by its own logins; the platform login reaches it through this routine alone, and a routine in `mcf` gives no USAGE on `demo`. Supersedes nothing (DEC-025bfc T1 to T3, T5 to T7 and DEC-89db41's plane and isolation decisions are unchanged).

## Rationale

- Foundation gate (DEC-79b62f). Location C (binding of the expected values a proof compares against) plus E (the custody record).
- Why not an upper layer: the source boundary (A) and contract semantics (B) are correct (41 of 41 months proved on 8e8a6f28); the gap is where expected values enter, which is a binding, so this is not compensation.
- Why not a lower layer: the emit, proof pin, snapshot and bridge (D, E) are reused, not bypassed; no row is hand-edited and the proof is unchanged.
- Design act (DEC-c48b0f): the source of the oracle's values changes (DEC-025bfc T4, the D2 rule), a declaration, recorded here; a detector would not fix it.
- Invariants: I (the reference feeds no evaluation), III (reference, month values and custody are trigger-immutable), IV (FK from custody to month value; custody to version stays the 0051 key, an ambiguous semver refused), V (reads never evaluate), VI (the custody set hash covers the WORM sha).

## Consequences

- The platform places any later non-ratio, single-currency metric with no per-metric pin and no hand-over file; Customer Invoice Count (version 8ec74fbd, 41 months, total 2699) is the first proven on it.
- The served login gains one deliberate reach (one routine), and bc-core's grant-drift TSV lists it in the same landing.
- Not yet covered: ratios with `not_defined` months (581 of 909 triaged have a division) and multi-currency metrics; a later step after Customer Invoice Count is proven. The currency custody column is deliberately not built.
- A placed version whose reference is later corrected cannot be re-placed (custody is unique per world, contract and semver); a new contract version is placed instead.
- Delivery order: bc-db 0092 PR with rollback, kit and restore proof; bc-core place command; one auditor landing (Lane: platform); one live window (apply 0092, serve move), with the standing prove and bridge rule asked as its own line of the live desk request. Authoring only for now: the engine-hold exception, merges, live apply and serve move each need their recorded grant. Decided on the owner's recorded desk grant 2026-11-27T09-38-58-907Z-7b27fb9a (request 665, text_sha256 7b27fb9a0434f65386c63003d0ac89d7ad0a7100e6fa50cd271e475de9a3568f).
- Docs follow-up: `docs/onboarding/prove-a-metric-version-on-the-demo-world.md`, the "answer sheet" and "hand over" steps become one "place" step.

## Alternatives rejected

- Interim route: a generator feeding the locked reference into the old answer-sheet hand-over, plus a hand-placed pin per metric. Rejected by the owner ("Build permanent route"); it keeps the owner-only pin and a file hand-over per metric.
- The proof reading the reference store directly: the served login and the proof path would reach the store at proof time, widening the reference's reach, and the proof's expected values would no longer sit in the immutable custody record the bridge hashes.
- The parked two pin doors (0090: `mcf.fn_pin_world_metric_version` and `contract.fn_pin_world_cc_version`): they place a pin but not the expected values, so a hand-over would still be needed; the canonical door is not needed to place a metric. Superseded; 0090 unused.
- Direct EXECUTE on the 0087 demo routines to the served login: needs USAGE on `demo`, which crosses the plane boundary DEC-89db41 and 0087's postcondition forbid.
