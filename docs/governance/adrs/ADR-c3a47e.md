# Governed wholesale fixture re-provision: the Inv-III boundary + the tenant-reset governed act (fixture-only), replacing world-stamp supersession as the Kaveri AP/AR clean-world mechanism

## Context

The Kaveri Wave-1 AP/AR re-provision's real critical-path blocker (caught in-window before any teardown) is that no governed path exists to start a fixture tenant clean: schema_provisioner is forward/desired-state only and the admission stores are append-only (TRUNCATE/DELETE refused in-DB). DEC-3926bf Amendment 1 (operator-granted, 2026-10-14) adopted a "wholesale fixture re-provision from v3_lc5" as the clean-world mechanism, resting its Inv-III-safety on "no row edited in place" — but it did not specify how the prior authoritative state and emitted evidence (DSO-validated, portal arc) are PRESERVED as addressable immutable history. A drop-to-empty that edits no row still destroys that evidence and makes prior versions non-addressable (Inv-III/VI). This ADR names the governed fixture clean-start act, bounds it to dev-fixture tenants (fail-closed guard), and COMPLETES Amendment 1's mechanism with the Inv-III/V/VI preservation model (archive the old tenant read-only + provision a fresh fixture identity) — so the capability is named, gated, bounded and preservation-safe rather than an undecided backdoor around immutability.

## Decision

Grounding: barecount-devhub artifacts/architect/SCOPE-SPEC-governed-fixture-reprovision-mechanism-2026-10-16.md — read its 2026-10-16 PRESERVATION ADDENDUM (@2f6eccc4 onward), which SUPERSEDES the original drop-to-empty build bytes (the @fded28e1 lines labelled "DB/Infra build spec" directing a tenant_reprovision drop/recreate are SUPERSEDED FOR IMPLEMENTATION by this ADR's archive-then-fresh model and MUST NOT be built or used as runbook authority). A clean archive-then-fresh SUCCESSOR spec + runbook/manifest is a BUILD-REVIEW PRECONDITION (next-act gate), not part of this ADR. Foundation basis: artifacts/architect/FOUNDATION-RULING-TSK-564901-world-stamp-reexamination-2026-10-14.md. This ADR COMPLETES the mechanism that DEC-3926bf Amendment 1 substituted (wholesale fixture re-provision) with the Inv-III/V/VI-complete PRESERVATION model it did not specify. Grounded read-only at origin/main: bc-core src/schema-provisioner/* (forward/desired-state only) + src/database/schema/progression.ts; bc-db migrations/tenant/0004_admission_run_context.sql (append-only UPDATE/DELETE/TRUNCATE trigger); foundation/the-invariants.md III/V/VI; DEC-3926bf Amendments 1+2; REPROVISION-RUNBOOK-2026-10-14. (Round 2: revised per Codex gen-ec24c4-01 — the preservation model + the D4 correction.)

D1 — PRESERVATION REQUIREMENT (the governing carve; Inv-III/V/VI). A fixture clean-start must PRESERVE the prior admitted state AND its emitted evidence (the DSO-validated 5/5 record, the Kaveri KPI portal arc, admission runs, lineage, D575 evidence) as RETAINED, IMMUTABLE, READ-ONLY, ADDRESSABLE history, SEPARATE from the new admission versions. This satisfies Inv-III (prior authoritative versions remain addressable indefinitely), Inv-VI (emitted evidence preserved, never destroyed), and Inv-V (the new admission is a FRESH act, not a reconstruction of the original). "No row edited in place" plus a restorable STEP-0 backup is a RECOVERY control (restore-if-the-run-fails), NOT preservation of the prior authoritative history as addressable immutable record — and is INSUFFICIENT on its own. Immutability forbids rewriting a tenant's history in place (row DELETE/UPDATE/TRUNCATE, refused in-DB); but a DROP of the admitted-state schemas ALSO destroys the emitted evidence and makes the prior versions non-addressable — so a drop-to-empty is NOT Inv-III-safe merely because it edits no row. Permitted ONLY for a DEV-FIXTURE tenant we own — never a customer tenant.

D2 — THE GOVERNED ACT = ARCHIVE-THEN-FRESH-PROVISION (not drop-to-empty). The fixture clean-start is: (1) ARCHIVE the current fixture tenant database as a read-only, IMMUTABLE, RETAINED, addressably-identified OLD-fixture database (writes revoked at the owner plane; retained indefinitely; separate custody) — the prior authoritative objects + emitted evidence preserved and addressable; (2) PROVISION a FRESH fixture tenant identity (schema_provisioner forward/baseline path) and re-admit from v3_lc5 in ONE governed pass carrying the extended surface (DEC-3926bf Amendment 1's AP+AR projections + Amendment 2's residual/as-of application-event surface); (3) advance the current-fixture reference to the fresh identity; (4) re-point the dependent arcs (the portal arc, metric bindings) to the fresh fixture. The OLD state is NEVER dropped — only archived read-only. (Codex named this design; an equivalent preservation mechanism that makes the prior state retained + immutable + addressable + separated may be substituted at build review.) SIX HARD CONDITIONS, all required: (i) WHOLESALE (archive+fresh-provision the entire fixture, never selective row ops); (ii) through the GOVERNED provisioning+admission path (never direct DB DELETE/INSERT/TRUNCATE, never an ad-hoc drop of the immutability triggers as a backdoor); (iii) the PRESERVATION of D1 PROVEN (old archived read-only + addressable) AND a STEP-0 recoverable+restorable backup PROVEN, both before the run grant is requested; (iv) a SEPARATE recorded operator grant, byte-bound to the runbook + manifest (distinct from the DEC-3926bf grants); (v) the reset act RECORDED with its own evidence written OUTSIDE the state being archived (Inv-VI — by whom, under which grant + preservation proof); (vi) FIXTURE-ONLY — a fail-closed classification guard refuses the act on any non-fixture/customer tenant, no override.

D3 — BUILD (specced for DB + Infra, built on their open): (DB/Infra) the ARCHIVE mechanism — snapshot/rename the old tenant DB to a read-only retained archive identity + revoke writes at the owner plane (immutable custody), proven addressable; plus FRESH-fixture provisioning via the EXISTING schema_provisioner forward/baseline path (no new destructive drop-to-empty command is required — archive replaces teardown); plus the governed re-admission RUNNER — verify the preservation proof + byte-verify the grant → provision the fresh fixture → governed admission from v3_lc5 via connection 01a07b9d (account.move + account.move.line + account.partial.reconcile) under the activated extended OCs, pinned to the v3_lc5 world → canonical eval → materialize → advance the current-fixture reference + re-point arcs → emit the reset evidence outside the archived state. BUILD-REVIEW GATES (Codex, to prove at build): the fixture classification comes from an AUTHORITATIVE tenant identity and FAILS CLOSED on missing/conflicting/changed classification; the command CANNOT target a customer database through the owner plane; retries and a partially-completed step are FENCED; any failed re-admission or post-rebuild oracle Δ is a RESTORE-and-HALT under the reviewed runbook. Idempotent. Any schema (command_type/columns) is a bc-db migration + DBCP + operator DB-yes, proven on an owner/grant-faithful restore clone.

D4 — WITHDRAWS the TSK-564901 world-stamp approach; NO new DEC-3926bf amendment (Amendment 1 already did it). The universal source_world_id column + supersession-by-reference (the original TSK-564901 design) is WITHDRAWN as lower-layer compensation (a universal storage-layer column for a dev-fixture concern that never fires in production; any genuine future selectable-world source repairs at the source contract (B) + binding (C), per-source, never a universal column). DEC-3926bf Amendment 1 (2026-10-14, operator grant 2026-10-14T12-20-14-535Z-0b835d21) ALREADY withdrew the world-stamp mechanism and substituted the single-pass wholesale fixture re-provision; the original D3b/D5/D6(c) world-stamp text is HISTORICAL, expressly overridden by Amendment 1 — so this ADR does NOT amend DEC-3926bf. Its contribution is to COMPLETE Amendment 1's mechanism: Amendment 1 rested its Inv-III-safety on "wholesale rebuild… no row edited in place" (the same insufficiency D1 corrects), without specifying the preservation of the prior authoritative history; this ADR supplies that preservation model (archive-read-only-old + fresh-fixture), making the substituted mechanism Inv-III/V/VI-complete. The ONE terminal pass RETAINS DEC-3926bf Amendment 2's residual/as-of surface (the amount_residual concept + the partial.reconcile dated-application leg) as a prerequisite. The clearing_date Option A design (DEC-93be49) and the rest of DEC-3926bf are unaffected.

Foundation gate (DEC-79b62f) — PASS. (1) Location: the admitted-state lifecycle / tenant-provisioning boundary — where a governed fixture clean-start with preservation belongs. (2) Not upper: the contaminant is a dev-workflow artifact (successive dump versions admitted into one long-lived fixture), not a production source property; the fix is the governed archive+fresh-provision, not a new source/contract declaration. (3) Not lower: a read/evaluator cannot un-contaminate admitted state, and a row-level wipe is (correctly) immutability-refused; the only sound path is the governed wholesale archive+fresh-provision with preservation. (4) Design act (DEC-c48b0f): names a missing GOVERNED CAPABILITY + its Inv-III/V/VI preservation boundary; the per-run archive/provision/re-admit is execution, operator-grant-gated. HARD RULE honored: no lower-layer compensation — the withdrawn universal column WAS such compensation; this ADR repairs at the right layer AND preserves prior authoritative history rather than destroying it.

## Amendment 1 (2026-10-16) — new-tenant governed onboarding supersedes the D2/D3 destructive mechanism

**Authority.** Operator-raised simplification (relayed by the Chief, 2026-10-16); Architect ruling `barecount-devhub artifacts/architect/RULING-new-tenant-vs-archive-then-fresh-2026-10-16.md @913d2c96`, Chief-accepted. Governed amendment: Codex review + a fresh recorded operator grant byte-bound to this amendment head.

**What changes.** D2/D3's DESTRUCTIVE mechanism — the owner-plane ARCHIVE recipe (rename/read-only/revoke), the fresh-identity-via-archive, the FIXTURE-ONLY classification gate + `admin.fn_assert_fixture_tenant`, the `infrastructure.fixture_reset_event` reset-ledger as a re-provision dependency, the off-tenant WORM seal, the STEP-0 backup as a teardown safety-net, and the DROP/rollback branches — is **RETIRED**. The Kaveri AP/AR clean-world method is instead **NEW-TENANT GOVERNED ONBOARDING**: onboard a NEW Kaveri demo tenant via the existing governed path (`POST /tenants`, ADR-103acb D3 completeness gate) with the FULL extended Track-2 contract set active, admit v3_lc5 into it, re-point the portal/KPI arc + metric bindings to it, and re-validate the metric set (STEP-F oracle). The existing `tbc_kaveri_dev` is **left fully intact and addressable** — preserved by NON-ACTION.

**Why (Foundation).** D1 PRESERVATION STANDS and is satisfied MORE strongly: non-action leaves the old tenant's authoritative state + emitted evidence (DSO-validated 5/5, the portal arc) fully intact and addressable — strictly stronger than the archive-read-only of the retired D2 (which renamed + revoked writes). The new tenant is a FRESH governed admission (Inv-V), not a reconstruction. It does NOT bypass the Track-2 contract-ACTIVATION gate — the new tenant's fresh-provision plans the sub-ledger `fact.*` from the ACTIVE bindings, identically. The `tbc_kaveri_dev` reuse was an INHERITED, unexamined assumption (DEC-3926bf Amd-1 "tear down tbc_kaveri_dev" → the 2026-10-14 fixture-clean ruling → Codex's fresh-identity nudge → this ADR's D2); since BOTH paths create a fresh identity and re-point the arcs, no reuse reason survives, and not-destroying is Foundation-stronger than any governed destruction.

**Re-point DEC-3926bf Amendment 1.** Its "tear down the demo tenant's (tbc_kaveri_dev) admitted state and reconstruct it" reference is re-pointed: the clean-world "fixture re-provision" is realized as a FRESH onboarded Kaveri tenant, not an in-place tear-down. DEC-3926bf Amendment 2's residual/as-of leg (amount_residual concept + the partial.reconcile dated-application admission) is unaffected and remains a later forward-additive admission into the NEW tenant (the defer per the reconcile @c7d1c3b7; DEC-3926bf Amendment 3 self-paced).

**Sequence (governed by existing ADRs; NOT blocked on this amendment).** (1) Track-2 contract activation (same gate); (2) governed tenant onboarding `POST /tenants` for the new Kaveri tenant + the ADR-103acb D3 completeness gate (legal entity, per-entity KAVERI-IN calendar, v3_lc5 source binding via connection 01a07b9d) + the operator onboarding grant; (3) admit v3_lc5 → canonical eval → materialize; (4) re-point the portal/KPI arc + metric bindings to the new tenant (governed reference act; old stays addressable); (5) re-materialize + re-validate the metric set (STEP-F oracle, DSO to the cent == PR #281); (6) preservation = NON-ACTION (retire-from-live via the current-fixture reference, never by touching the old).

**Live schema disposition (0040/0041, already applied, now unused by this path).** `tenant.tenant_class_code` (fixture/customer) + the authoritative datname column are RETAINED and USED by the new path (classify the new Kaveri tenant `fixture`; populate its authoritative datname at onboarding — this also resolves the `tbc_kaveri` vs `tbc_kaveri_dev` ambiguity for all tenant ops). `infrastructure.fixture_reset_event` + `admin.fn_assert_fixture_tenant`/promote were destructive-mechanism-specific and are now INERT (additive, harmless live schema); they are FLAGGED for a future BATCHED bc-db hygiene retirement — NO rollback migration is authored now (disproportionate on empty/unused objects).

**Superseded artifact.** The archive-then-fresh build spec `barecount-devhub artifacts/architect/SPEC-archive-then-fresh-reprovision-SUCCESSOR-2026-10-16.md @94091f58` is superseded by this amendment; its reusable parts (contract-binding completeness / fresh-baseline-from-active-bindings) carry into the new-tenant onboarding build.

**Foundation gate (DEC-79b62f) — PASS.** (1) Location: the tenant-onboarding boundary (the governed clean-start of a fixture is a fresh onboarding). (2) Not upper/lower: unchanged — the clean-world need is met by a fresh governed admission, no new source/contract declaration, no read/evaluator patch. (3) Design act: retires a now-unnecessary governed capability in favor of the existing, stronger onboarding path; preserves prior history by non-action. HARD RULE honored — "no schema you won't use": the destructive-specific schema is flagged for retirement; the generally-useful classification/datname columns are retained and used.
