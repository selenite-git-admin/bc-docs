# Governed wholesale fixture re-provision: the Inv-III boundary + the tenant-reset governed act (fixture-only), replacing world-stamp supersession as the Kaveri AP/AR clean-world mechanism

## Context

The Kaveri Wave-1 AP/AR re-provision's real critical-path blocker (caught in-window before any teardown) is that no governed path exists to start a fixture tenant clean: schema_provisioner is forward/desired-state only and the admission stores are append-only (TRUNCATE/DELETE refused in-DB). DEC-3926bf Amendment 1 (operator-granted, 2026-10-14) adopted a "wholesale fixture re-provision from v3_lc5" as the clean-world mechanism, resting its Inv-III-safety on "no row edited in place" — but it did not specify how the prior authoritative state and emitted evidence (DSO-validated, portal arc) are PRESERVED as addressable immutable history. A drop-to-empty that edits no row still destroys that evidence and makes prior versions non-addressable (Inv-III/VI). This ADR names the governed fixture clean-start act, bounds it to dev-fixture tenants (fail-closed guard), and COMPLETES Amendment 1's mechanism with the Inv-III/V/VI preservation model (archive the old tenant read-only + provision a fresh fixture identity) — so the capability is named, gated, bounded and preservation-safe rather than an undecided backdoor around immutability.

D1 — PRESERVATION REQUIREMENT (the governing carve; Inv-III/V/VI). A fixture clean-start must PRESERVE the prior admitted state AND its emitted evidence (the DSO-validated 5/5 record, the Kaveri KPI portal arc, admission runs, lineage, D575 evidence) as RETAINED, IMMUTABLE, READ-ONLY, ADDRESSABLE history, SEPARATE from the new admission versions. This satisfies Inv-III (prior authoritative versions remain addressable indefinitely), Inv-VI (emitted evidence preserved, never destroyed), and Inv-V (the new admission is a FRESH act, not a reconstruction of the original). "No row edited in place" plus a restorable STEP-0 backup is a RECOVERY control (restore-if-the-run-fails), NOT preservation of the prior authoritative history as addressable immutable record — and is INSUFFICIENT on its own. Immutability forbids rewriting a tenant's history in place (row DELETE/UPDATE/TRUNCATE, refused in-DB); but a DROP of the admitted-state schemas ALSO destroys the emitted evidence and makes the prior versions non-addressable — so a drop-to-empty is NOT Inv-III-safe merely because it edits no row. Permitted ONLY for a DEV-FIXTURE tenant we own — never a customer tenant.

D2 — THE GOVERNED ACT = ARCHIVE-THEN-FRESH-PROVISION (not drop-to-empty). The fixture clean-start is: (1) ARCHIVE the current fixture tenant database as a read-only, IMMUTABLE, RETAINED, addressably-identified OLD-fixture database (writes revoked at the owner plane; retained indefinitely; separate custody) — the prior authoritative objects + emitted evidence preserved and addressable; (2) PROVISION a FRESH fixture tenant identity (schema_provisioner forward/baseline path) and re-admit from v3_lc5 in ONE governed pass carrying the extended surface (DEC-3926bf Amendment 1's AP+AR projections + Amendment 2's residual/as-of application-event surface); (3) advance the current-fixture reference to the fresh identity; (4) re-point the dependent arcs (the portal arc, metric bindings) to the fresh fixture. The OLD state is NEVER dropped — only archived read-only. (Codex named this design; an equivalent preservation mechanism that makes the prior state retained + immutable + addressable + separated may be substituted at build review.) SIX HARD CONDITIONS, all required: (i) WHOLESALE (archive+fresh-provision the entire fixture, never selective row ops); (ii) through the GOVERNED provisioning+admission path (never direct DB DELETE/INSERT/TRUNCATE, never an ad-hoc drop of the immutability triggers as a backdoor); (iii) the PRESERVATION of D1 PROVEN (old archived read-only + addressable) AND a STEP-0 recoverable+restorable backup PROVEN, both before the run grant is requested; (iv) a SEPARATE recorded operator grant, byte-bound to the runbook + manifest (distinct from the DEC-3926bf grants); (v) the reset act RECORDED with its own evidence written OUTSIDE the state being archived (Inv-VI — by whom, under which grant + preservation proof); (vi) FIXTURE-ONLY — a fail-closed classification guard refuses the act on any non-fixture/customer tenant, no override.

D3 — BUILD (specced for DB + Infra, built on their open): (DB/Infra) the ARCHIVE mechanism — snapshot/rename the old tenant DB to a read-only retained archive identity + revoke writes at the owner plane (immutable custody), proven addressable; plus FRESH-fixture provisioning via the EXISTING schema_provisioner forward/baseline path (no new destructive drop-to-empty command is required — archive replaces teardown); plus the governed re-admission RUNNER — verify the preservation proof + byte-verify the grant → provision the fresh fixture → governed admission from v3_lc5 via connection 01a07b9d (account.move + account.move.line + account.partial.reconcile) under the activated extended OCs, pinned to the v3_lc5 world → canonical eval → materialize → advance the current-fixture reference + re-point arcs → emit the reset evidence outside the archived state. BUILD-REVIEW GATES (Codex, to prove at build): the fixture classification comes from an AUTHORITATIVE tenant identity and FAILS CLOSED on missing/conflicting/changed classification; the command CANNOT target a customer database through the owner plane; retries and a partially-completed step are FENCED; any failed re-admission or post-rebuild oracle Δ is a RESTORE-and-HALT under the reviewed runbook. Idempotent. Any schema (command_type/columns) is a bc-db migration + DBCP + operator DB-yes, proven on an owner/grant-faithful restore clone.

D4 — WITHDRAWS the TSK-564901 world-stamp approach; NO new DEC-3926bf amendment (Amendment 1 already did it). The universal source_world_id column + supersession-by-reference (the original TSK-564901 design) is WITHDRAWN as lower-layer compensation (a universal storage-layer column for a dev-fixture concern that never fires in production; any genuine future selectable-world source repairs at the source contract (B) + binding (C), per-source, never a universal column). DEC-3926bf Amendment 1 (2026-10-14, operator grant 2026-10-14T12-20-14-535Z-0b835d21) ALREADY withdrew the world-stamp mechanism and substituted the single-pass wholesale fixture re-provision; the original D3b/D5/D6(c) world-stamp text is HISTORICAL, expressly overridden by Amendment 1 — so this ADR does NOT amend DEC-3926bf. Its contribution is to COMPLETE Amendment 1's mechanism: Amendment 1 rested its Inv-III-safety on "wholesale rebuild… no row edited in place" (the same insufficiency D1 corrects), without specifying the preservation of the prior authoritative history; this ADR supplies that preservation model (archive-read-only-old + fresh-fixture), making the substituted mechanism Inv-III/V/VI-complete. The ONE terminal pass RETAINS DEC-3926bf Amendment 2's residual/as-of surface (the amount_residual concept + the partial.reconcile dated-application leg) as a prerequisite. The clearing_date Option A design (DEC-93be49) and the rest of DEC-3926bf are unaffected.
