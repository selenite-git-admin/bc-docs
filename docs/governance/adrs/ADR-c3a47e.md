# Governed wholesale fixture re-provision: the Inv-III boundary + the tenant-reset governed act (fixture-only), replacing world-stamp supersession as the Kaveri AP/AR clean-world mechanism

## Context

The Kaveri Wave-1 AP/AR re-provision's real critical-path blocker (caught in-window before any teardown) is that no governed path exists to return a tenant's admitted state to empty: schema_provisioner is forward/desired-state only and the admission stores are append-only (TRUNCATE/DELETE refused). The Inv-III-safe basis — fixture-clean wholesale rebuild — was ruled 2026-10-14 but the mechanism was unbuilt and the prior world-stamp column was withdrawn, leaving DEC-3926bf D3b citing a withdrawn mechanism. This ADR promotes the ruling to a decided governed act with a fixture-only guard so the destructive capability is named, gated and bounded (never operable on a customer tenant) rather than an undecided backdoor around immutability, and corrects the stale D3b reference.

## Decision

Full grounding + DB/Infra build spec: barecount-devhub artifacts/architect/SCOPE-SPEC-governed-fixture-reprovision-mechanism-2026-10-16.md @fded28e1; Foundation basis: artifacts/architect/FOUNDATION-RULING-TSK-564901-world-stamp-reexamination-2026-10-14.md. Promotes that ruling to decided + defines the governed act. Grounded read-only at origin/main (bc-core src/schema-provisioner/*, src/database/schema/progression.ts) + REPROVISION-RUNBOOK-2026-10-14.

D1 — INV-III BOUNDARY (the governing carve). Admission immutability (Inv-III) forbids rewriting a tenant's history IN PLACE: row-level DELETE/UPDATE/TRUNCATE on the append-only admission stores (admission_run_context, the D575 evidence chain, etc.) is refused in the database, correctly — which is why a plain refresh/wipe of a contaminated tenant is refused. A WHOLESALE fixture rebuild is categorically different and Inv-III-SAFE: drop/recreate the tenant's ENTIRE admitted-state schema set to baseline-empty and reconstruct it from source in ONE clean governed admission pass. No row is edited in place; clean single-world provenance holds by construction. This is permitted ONLY for a DEV-FIXTURE tenant we own (e.g. tbc_kaveri_dev) — never a customer tenant carrying immutable evidence.

D2 — THE GOVERNED ACT (tenant_reprovision / fixture reset), with six HARD CONDITIONS, all required: (i) WHOLESALE (drop/recreate the entire admitted-state, never selective row ops); (ii) through the GOVERNED provisioning+admission path (never direct DB DELETE/INSERT/TRUNCATE, never an ad-hoc drop of the immutability triggers as a backdoor); (iii) STEP-0 recoverable+RESTORABLE backup PROVEN before the destructive grant is even requested (the runbook's 3-layer proof incl. DSO-on-restore); (iv) a SEPARATE recorded operator grant, byte-bound to the runbook + manifest (distinct from any ADR/DEC-3926bf grant); (v) RECORDED as a governed destructive act emitting its own evidence (Inv-VI — by whom, under which grant + STEP-0 proof); (vi) FIXTURE-ONLY — a fail-closed classification guard refuses the act on any non-fixture/customer tenant, no override. The act necessarily bypasses row-level immutability (a wholesale DROP removes the append-only tables + their triggers) — that is precisely why it is a NAMED, gated, fixture-scoped governed capability rather than an undecided backdoor.

D3 — BUILD (specced for DB + Infra, built on their open): (DB) a new governed provisioning command tenant_reprovision on the provisioning-command model — fixture guard FIRST (fail-closed), STEP-0-proof + operator-grant precondition refs (fail-closed), wholesale drop+recreate of the whole tenant data-schema set to the provisioner's baseline-empty via the forward DDL path, recorded via provisioning_command_transition; the command_type + columns are a bc-db migration + DBCP + operator DB-yes, proven on an owner/grant-faithful restore clone. (Infra) a governed one-shot re-admission RUNNER — verify preconditions + byte-verify the grant → invoke tenant_reprovision (teardown) → governed admission from v3_lc5 via connection 01a07b9d (account.move + account.move.line + account.partial.reconcile) under the activated extended OCs, pinned to the v3_lc5 world → canonical re-eval → re-materialize → emit Inv-VI evidence; idempotent; rollback = RESTORE from the STEP-0 backup on any failure or post-rebuild oracle Δ.

D4 — WITHDRAWS the TSK-564901 world-stamp approach + AMENDS DEC-3926bf D3b. The universal source_world_id column + supersession-by-reference (the original TSK-564901 design) is WITHDRAWN (lower-layer compensation: a universal storage-layer column for a dev-fixture concern that never fires in production; any genuine future world-version need repairs at the source contract (B) + binding (C), per-source, never a universal column). DEC-3926bf D3b (decided) STILL cites "the world/dump stamp + current-world selector of TSK-564901" as the AP/AR clean-world supersession prerequisite — that reference is now STALE. LIGHT-AMEND DEC-3926bf D3b: replace the world-stamp supersession-by-reference mechanism with "demo-tenant fixture re-provision from v3_lc5 (single governed admission pass carrying the extended projection), per this ADR's governed tenant_reprovision act." The clearing_date Option A design (DEC-93be49) and the rest of DEC-3926bf are unaffected.

Foundation gate (DEC-79b62f) — PASS. (1) Location: the admitted-state lifecycle / tenant-provisioning boundary — where a wholesale rebuild is governed. (2) Not upper: the contaminant is a dev-workflow artifact (multiple dump versions admitted into one long-lived fixture), not a production source property; the fix is the governed rebuild, not a new source/contract declaration. (3) Not lower: a read/evaluator cannot un-contaminate admitted state, and a row-level wipe is (correctly) immutability-refused; the only sound path is the governed wholesale rebuild. (4) Design act (DEC-c48b0f): names a missing GOVERNED CAPABILITY + its Inv-III boundary; the per-run teardown/re-admit is execution, operator-grant-gated. HARD RULE honored: no lower-layer compensation — the withdrawn universal column WAS such compensation; this ADR removes it and repairs at the right layer.

HOLD: proposed. Decided-status + the DEC-3926bf D3b amendment + any execution each need a recorded byte-bound operator grant. Codex design review next (standing-authorized). No build/migration/DB op from this ADR.
