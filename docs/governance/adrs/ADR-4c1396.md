# bc-db spine is the sole platform schema authoring and apply path

## Context

Grounded 2026-09-20: live bc_platform_dev (273 tables) = ratified baseline (272) + spine 0006_onboarding_record; live has been spine-driven since the 2026-09-15 adoption (ledger: 9 legacy applies end 2026-09-08, then 0000 adopted + 0004-0007 spine applies); docker/redesign dormant since 2026-09-08 but no ratified rule routed the next change through the spine — an authority that other streams may still change is not an authority. Operator decided Option A (author directly in bc-db) on 2026-09-20; design accepted by independent auditor (RESPONSE-Codex-d597-412, bc-core PR #781 head 57a7aee5, APPROVED review 5259210926, merged a7e972f2).

## Decision

Every platform schema change is authored once as a bc-db forward migration (migrations/NNNN_*.sql, existing header contract, rollback where the protocol requires), independently reviewed at an exact head under the governed exchange, and applied to every environment only by the spine runner with one infrastructure.schema_migration_event row per apply. bc-core docker/redesign is frozen (no new migrations or DDL; CI-guarded) and retired in reviewed slices per docs/design/platform-db-unified-authoring-path.md §6. bc-core Drizzle types are regenerated surfaces, never the authority; local dev restores the S3 golden and applies pending spine migrations on top. Supersedes DEC-b1a286's designation of docker/redesign as the schema-change mechanism (its live-DB-as-observed-ground-truth content stands). Production apply remains Gate-④ operator-only.
