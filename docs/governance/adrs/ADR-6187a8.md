# Concept grounding of metric groups: a named Foundation grammar commitment

*Proposed. Recorded in DevHub as D695 with status proposed. It takes effect only with the owner's recorded landing grant, together with DEC-45200d. The full rule, worked examples and proof cases are in the proposal `docs/governance/proposals/foundation-amendment-concept-grounded-metrics.md` (revision 6) and the design `docs/reference/technical-notes/implementation/structured-group-design.md` (revision 3).*

## Context

A metric group names its grain and, sometimes, its date. Its other parts are free JSON (`template_json`, 24 distinct documents in 7 key shapes, read live 2026-11-26). The group version's grain and anchor have no foreign key, the anchor points at a concept identity rather than a concept version, and allowed values live in a JSONB array on the concept version. A member can therefore classify, sign or age records, and a group can name a concept without a version.

The owner ruled on 2026-11-26 that the structured group is concept-first and that this is a Foundation addition (barecount-devhub `artifacts/operator-review/DECISIONS-workflow-review.md`, entries `5b12384f`, `dfffb1a9`, revision 4's "Yes, both", `060d5328`, `1ef2d04e`, `53e9659c`, `ab2d086f`).

The auditor answered three times: gen-52eda8-01 (ACCEPTED WITH BOUNDARY, with the ADR-set paragraph this record follows), gen-52eda8-02 (CHANGES REQUIRED: B1, B2, N1), and gen-339991-01 (bc-external-audit `7f2a41d1`, ACCEPTED WITH BOUNDARY for the proposal at bc-docs `f0fbe983` and the group design at `5f7cc4ce`). The auditor's boundary: accepted design wording is not Foundation landing authority; the owner keeps the landing go and the ADR-set decision.

## Decision

1. **Adoption.** Sections 3.1 to 3.9 of the proposal are adopted as a named grammar commitment, "Concept grounding of metric groups", in `the-contract-grammar.md` (Metric Directory Member family), with coordinated explanation in `the-invariants.md` and a correction of `metric-directory.md` §6 item 2 (aging buckets are a typed temporal choice, not canonical values). The Foundation erratum is FND-ERR-010; these edits ship in the same landing, so it lands `closed`. No invariant is added.

2. **Standing.** The invariants govern authoritative evaluation and references. A group is governed intent under DEC-5a9dee 2c. Invariant IV governs references to authoritative objects; this grammar imposes the stronger version pin on directory intent. Invariant I gives the boundary rule (meaning is evaluated once, at the canonical boundary); this grammar enforces it for members.

3. **Two explanatory disallowed behaviours** in `the-invariants.md`. Under IV: a directory part named by free text, by a key inside JSON, or by a concept identity without a version. Under I: a member that classifies, signs or ages records.

4. **The rule.** A metric group version is made of semantic references (pinned entity or concept versions: grain, measure concept, anchors, axes, the event input's parts, and any one-step target, each reached on the grain or by one declared step) and typed governed parameters (measure kind, time class, age bounds, signs, period offsets, constants). Members select governed values on axes and never classify records. Selection relative to the evaluation point P is declared in the metric contract. A residual group declares its starting amount concept and its result concept separately, and a swap is refused. A one-step reach and an event input pin the exact target and event Canonical Object version sets, and each evaluation records the versions it used in Lineage.

5. **Design rules.**
   - Every semantic reference is a foreign key with its role check; every parameter is a typed column.
   - Grounded parts, a derived definition's inputs and period offsets included, live only on the group version, which each definition pins.
   - The old member columns and tables that repeat group parts (`template_json`, `member_version_direct_input`, `member_version_dependency`, `member_version_discriminator`, and `member_version`'s grain, temporal and output intent columns) stay for every historical version, and the database refuses new writes to them, or, where a column is part of a member version's content hash, accepts only the group version's value. A later drop takes only what no past version's content hash, directory projection or closure fingerprint reads (Invariant III).
   - No parallel tables (DEC-1918d0 rule 4).
   - Breakdowns are a separately versioned, immutable set keyed to a group version; the metric contract's output context pins one set version.
   - A metric contract realizes a member version only by role-by-role equality on semantic role and pinned version (proposal section 3.5).
   - Re-pointing a grain creates a new group and archives the old one, whose code stays reserved.
   - Every new definition version is realized by a new metric contract, joined to its predecessor by a `mcf.metric_supersession` record; the directory member carries the lasting identity.

6. **Order of units.** (1) this ADR and DEC-45200d, one decision unit, with FND-ERR-010 and the Foundation text edits; (2) the group design (TSK-09855b); (3) Unit V, typed allowed values; (4) the group, breakdown and member schema; (5) the sweep of all groups; (6) new metrics on the metric lane. Each later unit is its own act.
