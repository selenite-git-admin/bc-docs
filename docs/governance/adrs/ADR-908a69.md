# registerSourceStack authors OVER the admitted catalog — no catalog creation, object_type='table' gate

## Context

When D511 shipped, admission was NOT the catalog authority, so registerSourceStack deliberately added object/field creation (its header: "the D268-safe replacement for the deprecated bulk generator which assumes objects already exist"). That premise no longer holds. Today ExtractAdmissionService owns catalog creation with full governance: object_type classification (D562/D563), D559 typing (source_type_mapping), derivation facts, manifest/byte binding, and D564 keeps it clean (whitelist at the door + expunge for legacy contamination).

Against that, registerSourceStack's surviving mint-path is a RE-CONTAMINATION BYPASS: ensureObject-create stamps a source_object with object_type defaulted to 'table', no D559 typing, no manifest binding, catalog_status forced 'approved' — exactly the mislabeled-as-table defect class the whole D562/D563/D564 arc just closed (the Odoo A-gap; 10 contaminants expunged 2026-08-09). Two independent paths creating catalog objects is the precise hazard to eliminate before scaling SC/AC to ~250-300 business-module tables. It is dormant today only because callers happen to pass pre-admitted objects (account.move found-existing); at program scale a single non-admitted table would mint a bypass row.

Foundation: this is the fixed object progression — admission POPULATES the catalog; contracts are AUTHORED over it (the-invariants: meaning is evaluated once, at its boundary). Contract authoring re-creating catalog rows violates that separation and Invariant VI (the declaration must be READ from the emitted catalog, not re-inferred from a terse input). The object_type='table' gate makes the admissibility invariant explicit AT the contract boundary rather than trusting upstream.

D268 Rule 1 (no bulk contract chain generation) reconciliation for Phase C: SC is the MOST source-faithful layer — a deterministic projection of a catalog whose meaning was already established once at admission (Inv I). Projecting an already-governed, typed backbone into SC/AC form, per object, with every validator running and per-object verification (one-then-many), is not the prohibited generation of ASSERTED meaning in the canonical/metric layers (OC/CC/MC), where meaning is created. This ADR is the explicit decision that authorizes catalog-projection authoring at the source layer and draws that line.

## Decision

registerSourceStack (RegisterSourceStackService, D511/DEC-f4084d) is REPOINTED from create-and-author to AUTHOR-OVER-ADMITTED:

1. INPUT shrinks from a full SourceStackSpec (with a terse fields[] and objectType) to an ADMITTED OBJECT IDENTITY — either {objectId} or {moduleId, table, systemVersionId} that resolves an EXISTING source_object. systemCode/moduleCode/systemVersionId are resolved from the object's chain (object -> module -> version -> system), not supplied.
2. FAIL-CLOSED on absence: if no admitted object resolves, the call is REFUSED (BadRequest), never a create. The ensureObject-create branch and ensureFields are REMOVED. Admission (ExtractAdmissionService) is the sole catalog-creation authority.
3. ELIGIBILITY GATE: after resolving the object, assert object_type_code = 'table'; otherwise refuse ("not an admissible source table"). Contracts are authored only over real source tables.
4. UNCHANGED: readCatalogFieldSpecs (the SC/AC declaration is read from the ADMITTED, D559-typed catalog — source_field LEFT JOIN source_field_typing), ensureContractStack, D560 identity dedup (source_object_id, source_version_id, category), born-nameless naming, activation, every validator (D284 veracity, meta-schema, lifecycle). dryRun previews from the catalog for an admitted object (fail-closed if absent).

BLAST RADIUS: RegisterSourceStackService, its controller + DTO, register-source-stack.build.ts (SourceStackSpec loses required fields[]/objectType), the devhub_register_source_stack tool input, and specs. No internal service-to-service callers.

ENABLES the TSK-1e2fde Phase C batch driver: enumerate admitted object_type='table' objects in the in-scope business modules and author SC/AC per object, verified one-then-many. Batch authoring over the admitted catalog is a source-faithful PROJECTION of an already-governed backbone, NOT bulk chain generation (see rationale) — every per-object author still runs all validators.

This AMENDS D511/DEC-f4084d in one respect (retires its catalog-creation capability); the rest of D511 (single governed SC/AC stack, D560 identity, born-nameless) stands.
